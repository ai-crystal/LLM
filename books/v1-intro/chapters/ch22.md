## 这个系列怎么读

一次线下的技术聚会上，三个人前后脚问了同一个问题：接下来该看什么。

第一个人在做一款面向律师的文档工具，模型直接用服务商的接口，不自己训。他想知道检索那块到底怎么做才不会答非所问，以及一份合同扔进去，成本大概多少。

第二个人在一家做行业模型的公司，日常工作是清洗数据和跑训练。他想知道为什么他们的模型在长文档上总比不过别人，是数据问题还是结构问题。

第三个人在读研，导师让他复现一篇关于混合专家的论文。他想知道从哪补起，能不能直接读论文。

三个人问的是同一件事——信息在哪一册——但答案完全不同。这一章给一张地图：这套书分成哪十一个方向，每个方向回答什么问题，以及三条常见的读法。

地图的用法不是从头看到尾，而是先想清楚自己手上要解决的是什么，再去找对应的地方。册与册之间有依赖，但不是十一个台阶：应用那几册几乎不依赖训练细节，而训练那几册必须从“一句话怎么算出来”讲起。搞错入口的典型症状是读得很吃力，却不知道吃力在哪里。

### 十一个方向

| 方向 | 回答什么问题 |
|:-----------------------|:-----------------------------------------------|
| 入门 | 大模型是什么，能做什么，不能做什么，一次调用大概花多少钱 |
| 基础 | 一句话的下一个词是怎么算出来的 |
| 数据与规模 | 用什么语料、怎么清洗、怎么定预算 |
| 结构与改造 | 在固定算力和显存下，怎么让模型更好用 |
| 对齐 | 怎么把“接话机器”变成“助手” |
| 安全与攻破 | 这套“该不该做”的判断有多容易被绕开 |
| 推理与部署 | 怎么让它跑得快、跑得便宜 |
| 应用与 Agent | 怎么让它查资料、调工具、把多步任务做完 |
| 多模态 | 图像、声音、视频怎么变成 token |
| 训练工程 | 怎么把一万张卡连起来还不崩 |
| 可解释性与评测 | 模型内部在发生什么，以及怎么证明它变好了 |

十一个方向听着多，其实只有两个源头：一是“下一个词怎么算”，二是“算出这个词要花多少钱”。其余九个方向都是在这两个源头上做取舍。

### 两个源头，九个取舍

“下一个词怎么算”这条线，往下拆是模型的结构：词怎么变成向量，注意力在做什么，位置信息怎么表示，几十层怎么叠起来，参数量、计算量、显存怎么换算。这一条线回答的是“它为什么能算出这个分布”。

这条线有一个特点：越往下越像数学，越往上越像工程。词向量和注意力是数学，参数量和显存换算是算术，而“这个改动值不值得做”是工程判断。多数人需要的不是最下面那一层，而是中间那一层加上判断力：知道一个改动大概影响什么，能估出代价，能判断值不值。

“算出这个词要花多少钱”这条线，往下拆是系统：一次生成分几段，瓶颈在算力还是在带宽，缓存怎么管，批怎么排，量化到什么程度还能用，一台机器能服务多少人。这一条线回答的是“同样的能力，为什么有的产品便宜一半”。

其余的九个方向，都能挂到这两条线的某一段上。数据决定它见过什么前文；规模决定它能压进多少规律；对齐决定它在什么场合说什么话；攻破揭示这套判断有多脆弱；检索和工具决定它在预测之前能看到什么、能做什么；多模态是把图像和声音也变成 token；训练工程决定这件事在多大的规模上还成立；可解释性和评测决定你能不能证明它变好了。

所以读任何一册时都可以问一句：这一节在改“预测下一个词”的哪个环节。答得出来，说明读进去了；答不出来，多半是那一节还没读透。

### 三条路线

十一个方向不必按顺序读完一整遍。每一册都有独立的前言，会交代读完能做什么、需要什么基础，你可以从任何一册进入。但入口选错了，读起来会很吃力，所以有三条常见的走法。

**应用路线，给做产品的人。** 从入门开始，然后直接跳到应用与 Agent，再回头补推理与部署里讲成本和容量的部分，最后补基础里的核心概念。要微调时，读对齐里讲指令微调的部分；要碰智能体，读应用那一册最后讲多步任务的几章。这条路大概四到六周，目标不是会训模型，而是能判断一个需求能不能做、大概要多少成本、失败会在哪里。走完之后，你看一份模型接口文档，应该能立刻算出这个功能的毛利。

**训练路线，给要训模型的人。** 按入门、基础、数据与规模、结构与改造、对齐、安全、训练工程的顺序走，大概七八个月。这条路上每一册都要动手：写出一个小模型，跑一次预训练，改一处结构看损失怎么变，做一次微调，试着攻破自己的模型，再把训练压到多卡。只看不练，这一路读不下去，因为很多结论只有在损失曲线不降的时候才有体感。

这条路最容易被低估的是推理与部署。很多人觉得部署是“工程师的活”，与训练无关；实际上一个改动在训练时省下的算力，可能在推理时十倍找回来，不知道推理怎么花钱，就做不对训练时的取舍。

**研究路线，给要读论文的人。** 先把入门和基础读透，然后按方向挑一册精读，同时读原文：做对齐的读对齐册，做系统的读训练工程册，做安全的读安全册，做可解释性的读最后一册。这一路的关键差别是：不只读结论，要跟着论文把方法、实验、消融一节一节看过去，遇到没交代清楚的数字，回原文找。走完这一路，你拿到一篇新论文，应该能在一小时内判断它值不值得细读。

| 路线 | 从哪进 | 多久 | 走完能做什么 |
|---|---|---|---|
| 应用 | 入门后直接进应用 | 四到六周 | 判断需求可不可做、成本多少 |
| 训练 | 基础、结构、对齐、工程 | 七八个月 | 跑通一次完整训练 |
| 研究 | 入门加基础，再精读一册 | 三到六个月 | 一小时内判断论文值不值得读 |

三条路的时间差得很多，但它们有一条共同的起点：先把入门这一册读透。不是因为后面的内容依赖它，而是因为它给了你一套提问方式。不知道“预测下一个词”意味着什么的人，读训练那一册会把所有优化都当成工程技巧；不知道 token 是什么的人，算成本时会少算一半。

### 一个具体的例子

把开头那个做律师工具的人摊开看，他的读法大概是这样。

第一周读入门，把“预测下一个词”这件事弄明白，把 token、上下文、成本这几个词弄准。这一周不解决他的问题，但决定了他后面读东西时能不能对上号。

第二周读应用与 Agent 里讲检索的部分，同时动手：拿二十份自己的合同，切块、建索引、跑十次提问，看召回准不准。他会发现，他的问题不在模型，在切块和重排。

第三周读推理与部署里讲成本和容量的部分，算出他的一百次审阅一天要花多少钱，以及为什么长合同比短合同贵那么多。这一周他会改一个设计：不整份合同送进去，先检索出相关章节。

第四周读可解释性与评测里讲私有评测的部分，建一份六十条的评测集，把“漏掉关键条款”“把主体搞反”分开记。这之后他换模型、改提示，都有依据了。

四到六周，他没有学会训模型，但他能判断这个需求能不能做、成本在哪、失败会长什么样。这就是应用路线的目标：不是造工具，是用工具做出对的判断。

同一条路换成训练工程师，读法完全不同：他会把大部分时间放在基础、结构与改造、训练工程上，而且每一节都要跑一遍代码。地图一样，走法不一样。

### 算一遍：读完要多少小时

把时间算清楚，路线才落得下来。

十一册按平均两百页算，两千两百页。技术书一小时能细读的页数，加上停下来想和查资料，大概是十五到二十五页，取二十。

两千两百除以二十，一百一十小时。每天一小时，是三个半月；每天三小时，是五周半。

这个数字要修正两处。第一，应用路线不需要全读，四到六册足够，六七十小时。第二，训练路线的每一册都要动手，跑代码的时间通常是读书的两三倍，所以七八个月不是虚的。

还有一个更实际的算法：按问题算，不按页算。你手上有一个具体问题，找到对应的两三章读完，六到十小时就能形成判断；而漫无目的地从第一页读到最后一页，往往读到一半就停了，因为看不到这些问题和自己有什么关系。

这也是这一册可以跳读的原因：它的每一章都是按“一个问题”组织的，不是按“一个知识点的顺序”组织的。

### 这一册可以跳着读

这一册的定位是“浅而全”：每一章只讲清“是什么、为什么这样、代价是什么”，不推公式，不出现矩阵和梯度。它的目标不是让你会做，而是让你在听到一个说法时知道该问什么。

所以它可以跳读。手上有具体任务的，先看对应的那几章：要算成本看账单和部署那两章；要选模型看评测和模型来源那两章；要接业务系统看用法、记忆、工具那几章。每一章都能独立读，结尾那三条是这一章的抓手。

想从头读一遍的，可以按五段的顺序走：它是什么、怎么训出来、能干什么、怎么用怎么算账、边界与地图。前三段是理解，第四段是判断，第五段是把判断落回现实。

如果只有两个小时，一个不错的挑法是：第 1 章（它在做什么）、第 14 章（它会什么不会什么）、第 16 章（钱花在哪）、第 21 章（会出什么事）。四章读完，你对这个东西的判断力已经够用了，剩下的都是在这四章上加深。

### 这张地图没画的地方

地图有用，是因为它省略了很多东西。说清楚省略了什么，你才知道什么时候该离开这张图。

它不讲硬件供应链。显卡怎么造、产能怎么分配、集群怎么建，这些决定了模型能不能训出来，但它们属于另一个领域，和“模型怎么工作”关系不大。

它不讲组织和流程。一个团队怎么分工、评测谁来做、上线审批走几道，这些决定了同样的技术能不能落地，但它们是管理学问题。

它不讲产品设计。用户该看到什么、什么该自动什么该确认、错误怎么呈现，这些决定了产品好不好用，和技术是两件事。

它也不讲法律细则。版权怎么判、数据合规怎么做、责任怎么划分，这些因地区而异，而且一直在变，只能看具体的法规和判例。

当你的主要问题落到这四项里时，这张地图只能帮你把技术那一半说清楚，另一半得找对应领域的人。这个分工不是推卸，是承认边界：技术判断能告诉你能不能做、代价多少，不能告诉你该不该做。

### 回到“预测下一个词”

把十一个方向摊开，看起来是八个领域：数据、结构、对齐、安全、推理、应用、多模态、训练工程。但它们都能挂回同一句话上。

给定前文，预测下一个 token。数据决定了它见过什么样的前文；结构决定了它怎么利用这段前文；规模决定了它能把多少规律压进参数；对齐决定了它在什么场合说什么话；攻破揭示了这套场合判断有多脆弱；推理系统决定了它多快、多便宜地把这句话说出来；检索和工具决定了它在预测之前能先看到什么；多模态是把图像、声音也变成 token，让同一套机制去处理；训练工程决定了这件事在多大的规模上还成立。

所以这些方向没有一个是“另一件事”，它们是同一件事的不同侧面。

这一册到这里就结束了。它没有教你训模型，也没有教你推公式，它想给你的是一套判断力：看到一个模型发布，知道该看哪几个数；听到一个“颠覆”的说法，知道该问什么；接到一个需求，知道它落在哪一种用法里；遇到一次答错，知道该修数据、修检索，还是修提示。

这套判断力不会因为模型换代而过时，因为换代改的是分数，不改的是那几个问题。

### 四个常见的误解

第一个误解是“读完了就会训模型”。读书给你的是判断力，不是手感。损失曲线不降、通信卡住、评测分数和体感相反，这些只有在机器前面才知道怎么办。

第二个误解是“越难的那册越值得读”。难度和用处不成正比。做产品的人读结构改造那一册，收益远小于读成本和评测那两册。

第三个误解是“必须按顺序读”。册与册之间有依赖，但不是台阶。应用类的内容几乎不依赖训练细节，而训练类的内容必须从“一句话怎么算出来”讲起。入口选错，就会读得很吃力。

第四个误解是“看完这一册就不用看别的了”。这一册刻意不讲公式、不讲矩阵、不讲梯度，它给的是地图和判断力。真要动手，还得回到那一册里去。
