## 训练目标与损失：它到底在优化什么

一次前向走完，模型在最后一个位置吐出五万个 logits。这五万个数字里有一个对应着语料里真实出现的下一个词，其余四万九千九百九十九个都不对。

问题就在这里：模型怎么知道“错”了多少？它输出的不是答案，是一个分布；语料给的也不是分数，是一个整数编号。要把这两样东西对起来算出一个可以求导、可以反向传播的数，中间需要一次翻译。这次翻译定义了整个训练在优化什么，也决定了模型会养成什么习惯——包括那些后来需要对齐才能纠正的习惯。

这一章把这个数拆开：一个位置的损失长什么样，为什么必须是负对数，一句话的几十个损失怎么合成一个，以及为什么不能直接用准确率。

### 一个位置的损失

先把符号摆好。词表大小记作 $V$（五万到二十万之间的一个整数）。第 $t$ 个位置的输出向量 $h_t\in\mathbb{R}^{d}$ 经过输出投影，得到一个 $V$ 维的向量：

$$z_t=Wh_t\in\mathbb{R}^{V}$$

$z_t$ 叫 logits，每个分量对应词表里的一个 token。它可以取任意实数，有正有负，本身没有意义——把整个向量加 100，softmax 之后结果完全不变。只有分量之间的差有意义。

softmax 把 logits 变成概率：

$$p_t=\mathrm{softmax}(z_t),\qquad (p_t)_v=\frac{\exp\big((z_t)_v\big)}{\sum_{u=1}^{V}\exp\big((z_t)_u\big)}$$

$(p_t)_v$ 是“下一个词是词表第 $v$ 个 token”的预测概率，所有分量非负、加起来等于 1。

标签是一个整数 $y$，就是语料里真实的下一个 token 的编号。损失取

$$\ell_t=-\log\big((p_t)_{y}\big)$$

就这一行。模型给正确词的概率越高，损失越小；给得越低，损失越大。概率是 0.9 时损失 0.105，0.5 时 0.693，0.1 时 2.303，0.01 时 4.605。如果模型完全瞎猜、五万个候选均匀分布，正确词的概率是 $1/50000$，损失是 $\ln 50000\approx10.82$。

这几个数字值得记住，它们是后面所有“损失降到多少算正常”的参照。一个刚初始化的模型，损失应该贴着 10.82；如果它一开始就是 3，说明输出层初始化有问题，或者标签对齐错了。

注意一件事：这个损失只关心正确词那一项，其余四万九千九百九十九个数被完全忽略了——不是被当成 0，是根本没进公式。这一点很反直觉，但它是对的：softmax 的分母里已经包含了所有 logits，压低任何一个错误词的分数都会让正确词的概率上升，所以“错的部分”通过分母间接参与了优化。这也解释了为什么不需要给每个错误词单独设惩罚。

### 交叉熵：为什么是负对数

$-\log p$ 这个形式不是随手挑的。它有一个名字，交叉熵（cross-entropy），来历值得走一遍，因为它决定了损失的很多性质。

先看信息量。一个事件发生的概率是 $p$，它携带的信息量定义为 $-\log p$。概率 1 的事件不带来任何信息（$-\log 1=0$）；概率 0.01 的事件一旦发生，信息量是 4.6。用对数而不是别的函数，是因为信息量应该可加：两个独立事件同时发生，概率相乘，信息量应该相加，只有对数能把乘法变成加法。

交叉熵衡量的是“用分布 $q$ 去编码来自分布 $p$ 的事件，平均要花多少信息量”：

$$H(p,q)=-\sum_{v=1}^{V}p_v\log q_v$$

$p$ 是真实分布，$q$ 是模型的预测。在我们的场景里，$p$ 是一个 one-hot 分布——只有正确词那一项是 1，其余是 0。代进去，求和里只有一项留下：

$$H(p,q)=-\log q_y$$

和上面那个式子完全一样。所以“负对数损失”和“交叉熵”是同一件事的两种叫法。

第二个理由更本质。把交叉熵拆开：

$$H(p,q)=\underbrace{H(p)}_{\text{真实分布的熵}}+\underbrace{D_{\mathrm{KL}}(p\,\|\,q)}_{\text{两个分布的差距}}$$

$H(p)$ 只与数据有关，与模型无关，是个常数。所以最小化交叉熵等价于最小化 KL 散度——也就是把模型输出的分布往真实分布上拉。这个视角解释了为什么语言模型训练到最后，损失不会降到 0：真实的语言本来就有不确定性，“今天天气真”后面接“好”还是“不错”都可能，模型能做到的最好情况是把这几种可能按语料里的频率分配，剩下的那部分熵是数据自己的，不是模型的错。

第三个理由是它和最大似然是一回事。语言模型定义的是整段文本的概率：

$$p_\theta(x_1,\dots,x_T)=\prod_{t=1}^{T}p_\theta\big(x_t\mid x_{<t}\big)$$

$x_{<t}$ 表示位置 $t$ 之前的所有 token。这个式子说的是：整句的概率等于每个位置“给定前文预测当前词”的概率连乘。训练的目标是让训练语料在这套参数下的概率最大，也就是最大似然估计（maximum likelihood estimation，MLE）。概率连乘容易下溢，取对数变成求和：

$$\log p_\theta(x_{1:T})=\sum_{t=1}^{T}\log p_\theta\big(x_t\mid x_{<t}\big)$$

最大化它，等价于最小化它的相反数，而每一项正是 $-\log p_\theta(x_t\mid x_{<t})$。所以“最小化交叉熵”和“最大似然”是同一件事的两种说法，一个从信息论来，一个从统计来。

第四个理由在梯度上。把 $L=-\log q_y$ 对 logits 求导，只需要三步。先展开：

$$L=-z_y+\log\sum_{u=1}^{V}\exp(z_u)$$

第一项对 $z_j$ 求导，只有 $j=y$ 时是 $-1$，其余是 0，写成 $-1[j=y]$，$1[\cdot]$ 是示性函数，条件成立取 1。第二项先对求和号里的第 $j$ 项求导，得到 $\exp(z_j)$，再除以整个求和：

$$\frac{\partial}{\partial z_j}\log\sum_{u}\exp(z_u)=\frac{\exp(z_j)}{\sum_{u}\exp(z_u)}=q_j$$

合起来：

$$\frac{\partial L}{\partial z_j}=q_j-1[\,j=y\,]$$

**梯度就是“预测减标签”。** 这句话值得停一下。模型预测正确词的概率是 $q_y$，那么这个分量上的梯度是 $q_y-1$，一个负数——梯度下降会把这个 logit 往上推，推的力度正比于 $1-q_y$，也就是“还差多少”。其余每个分量的梯度是 $q_j$，一个正数，会把它往下压，压的力度正比于它现在分到多少概率。预测完全正确时（$q_y=1$，其余为 0），整个梯度向量是零，没有更新。

这个形式极其干净：没有多余的因子，没有分母上的雅可比矩阵。换成别的损失函数（比如平方误差配 softmax），梯度里会多出一堆 $q_j(1-q_j)$ 之类的项，训练早期梯度被压得很小，学得慢。softmax 配交叉熵之所以成为标准搭配，一半原因就在这里。

### 一句话的损失怎么合成一个数

一个位置算完了，一句话有 $T$ 个位置。它们的损失怎么合？

先对齐标签。输入是 $x_1,\dots,x_T$，位置 $t$ 的输出应该预测 $x_{t+1}$。所以位置 $t$ 的标签是 $x_{t+1}$，整句话的损失是

$$L=\frac{1}{T-1}\sum_{t=1}^{T-1}\Big[-\log p_\theta\big(x_{t+1}\mid x_{\le t}\big)\Big]$$

两个细节容易出错。第一，位置 1 到 $T-1$ 才有标签，最后一个位置的预测没有对应的“下一个词”，白算。第二，位置 $t$ 能看到的只有 $x_1$ 到 $x_t$，这是因果掩码保证的；如果掩码写错，位置 $t$ 会看到 $x_{t+1}$，损失会异常低，训练看起来“特别顺”，上线之后一塌糊涂。这是最典型的静默故障之一。

除以 $T-1$ 而不是求和，是为了让损失的量级与长度无关。求和的版本会随序列长度线性增长，学习率得跟着长度调；平均之后每个 token 的权重相同，一个 8 token 的短句和一个 8000 token 的长文贡献一样的梯度尺度。这不是唯一的合理选择，但它是让不同 batch、不同长度能混在一起训练的前提。

“每个 token 权重相同”本身是一个建模假设，值得说清它假设了什么。它假设“的”“了”这种高频虚词和“因为”这种连接词、和文档标题里的关键词，对训练的价值一样。真实情况当然不是——虚词好学，梯度信号很快就饱和了，关键词和罕见词才是模型真正需要花容量的地方。所以后来的做法会在这一层做调整：按 token 加权、按文档质量加权、或者先按序列算平均再跨序列算平均（这两种嵌套顺序不等价，长文档多的 batch 会被压低权重）。

工程上还有两件事要处理。padding：一个 batch 里序列长度不齐，短句要补到最长，补出来的位置不算损失，分母也要把它们扣掉，否则平均会被稀释。跨 batch：通常是先在一个 batch 内按有效 token 数平均，再对多个 batch 的均值做平均；梯度累积时同理，每个 micro-batch 各自按自己的 token 数平均，不能简单相加。

### 算一遍：一句话的损失怎么摊平

损失取平均这一步看着无害，实际上决定了“什么算一个样本”。算法不同，同一个 batch 的损失能差 0.3 nat。

设一个 batch 有两条序列：A 长 2048，平均损失 2.0；B 长 512，平均损失 3.0。

按 token 平均：分子是 $2048\times2.0+512\times3.0=5632$，分母是 $2560$，得 $2.2$。

按序列平均：$(2.0+3.0)/2=2.5$。

差 0.3 nat，对应困惑度 $e^{0.3}=1.35$ 倍。差别来自权重：按 token 平均时，B 的每个 token 只占 $512/2560=20\%$ 的分母，短句被稀释；按序列平均时，B 占一半。

哪个对？取决于你怎么定义“模型的好坏”。如果关心的是“处理这批文本时每个 token 的平均代价”，按 token 平均对；如果关心的是“每条请求的平均体验”，按序列平均对。预训练关心前者，因为训练目标就是 token 级的预测；一些微调场景关心后者，因为一条长回答里的错误不该被长度加权。

这件事在梯度累积时会变得更微妙。如果 8 个 micro-batch 的长度不同，用“各自平均再求平均”和“先加总再除以总 token 数”得到的结果不一样，前者等价于按序列平均，后者等价于按 token 平均。分布式训练里常见的 bug 是：单卡验证时用 token 平均，多卡训练时每张卡各自平均再 all-reduce，两者不一致，于是训练损失和验证损失差一个系统性的偏移。这个偏移不会让训练失败，只会让“损失曲线对不上”这件事查很久。

还有一处更隐蔽的：padding 的分母。补齐的位置不算损失，但实现里如果只把它们的标签设成忽略而忘了从分母里扣掉，平均就会被稀释。$T=2048$ 的 batch 里如果有一半是补齐的，损失会凭空小一半，而且随 batch 组成波动。这类 bug 的症状是“损失曲线抖动很大但趋势正常”，很容易被当成数据噪声。

### teacher forcing：训练时把答案喂进去

上面那套流程有一个隐含的选择，值得单独拎出来：位置 $t$ 的输入是语料里真实的 $x_t$，不是模型自己在第 $t-1$ 步生成的 token。这个做法叫教师强制（teacher forcing）——teacher 指真实标签，forcing 指强制把它喂进去。

为什么必须这样？两个原因，第一个是工程上的。如果位置 $t$ 的输入依赖位置 $t-1$ 的输出，整句话就只能串行生成，前面讲注意力时说的“一次算完所有位置”就全废了。用真实 token 当输入，$T$ 个位置的输入在训练开始前就全部已知，一次前向能算出 $T$ 份预测、$T$ 份损失，一次反向传播更新全部参数。并行不是省了一点时间，是把复杂度从 $T$ 次前向降到 1 次。

第二个原因在学习信号上，而且更关键。训练早期模型的输出基本是垃圾。如果拿自己的输出当前缀，位置 5 的输入就是一个随机 token，位置 6 的输入是另一个随机 token，整句话很快飘到训练分布之外。模型收到的梯度在教它“如何在一个已经被自己搞坏的前缀上继续往下接”，而推理时我们希望它“在正确的前缀上往下接”。这两件事不一样，后者才是要学的。

代价也有名字，叫暴露偏差（exposure bias）。训练时模型看到的每个前缀都是完美的，它从没见过自己犯错之后的世界；推理时前缀是它自己生成的，一旦某个词选错，后面的分布就落到训练时没见过的区域，误差会沿着序列累积。这就是为什么训练损失 1.5 的模型，自由生成一段长文时仍然可能在中途跑偏——训练时的 1.5 是在“前缀全对”的条件下测出来的。

这个落差不是小问题，它部分解释了为什么预训练之后还需要监督微调和强化学习：前者把“在人类写的前缀上接得准”变成“在人类偏好的回答上接得准”，后者直接优化“整段输出的好坏”，不再逐 token 对齐。有一些中间方案（计划采样、在训练中逐步混入模型自己的输出）试图缩小这个落差，但它们都会牺牲并行性，在大规模预训练里不划算。

到这里，训练目标的结构就完整了：一次前向、$T$ 份逐位置的交叉熵、平均成一个标量、反向传播。接下来要处理的是这个标量的读法——它是个正数，但它到底代表什么。

### 困惑度：把损失换成人能读的单位

损失是一个平均到每个 token 的负对数概率，单位是 nat（以 $e$ 为底的对数）。数字本身不好读：1.8 和 2.0 差多少？听起来差不多，实际上差得很明显。于是文献里普遍用另一个量：

$$\mathrm{PPL}=\exp(L)$$

$L$ 就是上面那个平均交叉熵，$\mathrm{PPL}$ 叫困惑度（perplexity）。用 $\exp$ 而不是别的底，是因为 $L$ 是以自然对数为单位的，取指数正好把它逆回去。

逆回去之后得到一个很具体的解释。假设模型在每一步都在 $k$ 个等概率的候选之间均匀猜，那么正确词的概率是 $1/k$，损失是 $\ln k$，困惑度正好是 $k$。所以困惑度读作：**模型每一步平均在多少个等概率候选之间犹豫。** $\mathrm{PPL}=20$ 就是“平均在 20 个词里选”，$\mathrm{PPL}=5$ 就是“在 5 个词里选”。这个说法精确到常数因子，用来建立直觉足够。

把常用值列出来，方便对上号：

| 平均损失 $L$ | 困惑度 | 含义 |
|---|---|---|
| 0.69 | 2.0 | 平均在 2 个词里选 |
| 1.10 | 3.0 | 大约在 3 个词里选 |
| 1.61 | 5.0 | 大约在 5 个词里选 |
| 2.30 | 10.0 | 大约在 10 个词里选 |
| 3.00 | 20.1 | 大约在 20 个词里选 |
| 4.61 | 100 | 相当于百词选一 |
| 6.91 | 1000 | 大约在千词里选 |
| 10.82 | 50000 | 完全均匀，等于没学 |

一个训练良好的英文模型在通用语料上的困惑度通常在 3 到 10 之间，具体数字极大取决于语料、分词器和评测方式，跨模型比绝对值意义不大。同一份数据、同一个分词器、同一个上下文长度下比，才有意义。

换一个单位也能读出信息量。把 nat 换成比特，除以 $\ln 2\approx0.693$：$L=2.30$ 对应每 token 3.32 bit。这个数字可以和“一个英文单词平均几个字母”放在一起看——英文的自然语言熵大约在每字符 1 bit 上下，一个 token 大约 4 个字符，所以 3 bit/token 意味着模型已经把大部分冗余压掉了。

困惑度有两个坑，踩过的人很多。

第一个坑：不能跨分词器比较。同一个句子，五万词表可能切成 20 个 token，十二万词表切成 16 个。词表大，单 token 携带的信息多，每 token 的损失天然更高，但这不代表模型更差。要跨分词器比，得换算成与切分无关的单位，比如每字符比特数（bits per character，BPC）：把总损失乘以 token 数，除以字符数。这是评测报告里经常被忽略的一步。

第二个坑：困惑度不衡量“回答好不好”。它只算下一个词的预测，而一段平庸、重复但高度可预测的文本可以有极低的困惑度。反过来，一个准确、丰富、有创造性的回答，因为用词不那么可预测，困惑度反而高。预训练看困惑度是因为目标就是预测，对齐之后的评测必须换成任务指标。两者不是同一个东西的两种刻度，是两个不同的东西。

顺带说一句损失曲线怎么读。刚开始的几步，损失从 10.8 跌到 4 左右，降得很快——这一段模型只学到了词频：“的”“the”这类高频词先拿到高概率，跟上下文无关。接下来从 4 降到 2.5，要靠局部搭配和语法。再往下每一个 0.1 都很贵，对应的是长距离依赖和事实性知识。曲线的形状是几个斜率递减的段拼起来的，每一段对应一类被榨干的规律。看到一个模型在 2.0 附近卡住两周不动，往往不是优化出了问题，是数据里能学的规律已经被这一档容量吃完了。

### 为什么不用准确率

这里有一个很自然的问题：既然目标是“预测对下一个词”，为什么不直接优化准确率——预测对了算 0，错了算 1？

第一个障碍是数学上的。准确率是一个阶跃函数，输出要么 0 要么 1，对参数的导数几乎处处为零。导数处处为零的函数没法做梯度下降，你无法从“错了”这个事实里读出“往哪个方向改”。所有基于梯度的训练都要求损失对参数可微，这是硬约束，不是偏好。

有人会说：那就用 top-1 准确率当监控指标。可以，但不能当训练信号，而且它会把很多真实进展掩盖掉。举个具体的场景：词表五万，正确词的当前概率是 0.20，排第三。模型把它的概率抬到 0.45，排到了第二——准确率一点没变，还是 0，但损失从 1.61 降到了 0.80，降了一半。模型确实学到了东西，它把正确词从“几乎不可能”推到了“差一点就中”；如果只看准确率，这段训练看起来完全停滞。

反过来也成立。一个模型准确率 40%，另一个 42%，前者的损失可能反而更低——因为它对正确的那些例子非常自信（概率 0.99），对错误的那些只是略微倾向错的那个（概率 0.4 对 0.35）。准确率只看排序，不看差距；交叉熵看整个分布的形状。在语言这种“下一个词本来就有多种合理选择”的任务上，分布形状比排序更重要。

还有一层：交叉熵是有下界的、可比较的。它衡量的是模型分布与数据分布的 KL 散度加上数据自身的熵，两个模型在同一份数据上的损失差，直接对应“多出来的那部分不确定性”，可以换算成比特、换算成压缩率。准确率没有这个性质——它只是一个比例，不告诉你错得有多离谱。

交叉熵的短处也要说清。它把每个 token 等同看待，一个虚词和一个关键词的权重一样；它衡量分布匹配，不衡量“整段输出是否有用”；它对已经学得很好的部分继续给梯度（概率从 0.99 到 0.999 还能降损失），这部分梯度对能力提升的贡献很小。所以大规模训练里常见到一种现象：损失稳定下降，下游任务却停在原地。训练用损失，评估用任务指标，这两个位置不能互换。

### 两个工程补丁：label smoothing 与 z-loss

上面那套目标函数是干净的，但直接拿去跑大模型会遇到两个具体麻烦，对应两个补丁。都不改变建模思路，只改变数值行为。

第一个是标签平滑（label smoothing）。它把 one-hot 目标换成一个“掺了沙子”的分布：

$$p_v^{\text{smooth}}=(1-\epsilon)\,1[v=y]+\frac{\epsilon}{V}$$

$\epsilon$ 是平滑系数，常取 0.1。意思是：正确词拿 $1-\epsilon$，剩下的 $\epsilon$ 平均分给全部 $V$ 个词。

它解决的问题是“模型被鼓励无限自信”。用纯 one-hot 目标时，最优解是把正确词的概率推到 1、其余全部压到 0，对应 logits 的差距趋于无穷。这在有限数据上就是过拟合：模型把训练集里“这个词后面必定接那个词”的巧合也当做铁律背下来，泛化变差。平滑之后，目标本身带有不确定性，模型把正确词推到 $1-\epsilon$ 附近就够了，logit 差距被限制在 $\log\big((1-\epsilon)(V-1)/\epsilon\big)$ 量级。原论文在 2017 年的翻译模型上报了约 0.4 BLEU 的提升。

但它在大模型预训练里用得很少，原因很直接：它把损失的地板抬高了。掺了 $\epsilon/V$ 之后，即使模型完全学对，最小损失也不是 0，而是目标分布自身的熵。对已经偏欠自信的大模型来说，这等于在目标里埋了一个降不下去的常数，而且它会削弱模型在需要时给出尖锐分布的能力。所以在预训练里它基本退场，在需要校准的判别任务里还在用。

第二个是 z-loss，来自 PaLM 的训练配置。它给损失加一项：

$$L_{\text{total}}=L_{\text{CE}}+c\cdot\Big(\log\sum_{v=1}^{V}\exp(z_v)\Big)^{2},\qquad c\approx10^{-4}$$

括号里那一项是 softmax 归一化常数的对数，记作 $\log Z$。为什么要惩罚它？因为 softmax 只看 logits 之间的差，把所有 logit 同时加一个常数，输出完全不变。这个“整体平移”的自由度在数学上无害，在数值上不无害：logits 整体漂到几十的量级时，$\exp(z_v)$ 在 bf16 里会溢出或者丢精度，训练突然出现 NaN。z-loss 把 $\log Z$ 钉在 0 附近，把这个自由度固定住。

它不改变模型的表达能力，也不改变最优解（在 softmax 不变的意义上），只改变数值稳定性。这类补丁在大规模训练里很常见：它们的价值不在数学上漂亮，而在把一次可能崩掉的训练变成能跑完的训练。

### 算一遍：label smoothing 把地板抬到哪

标签平滑的公式只有一行，但它的代价常常被低估。算一下地板。

$\epsilon=0.1$、$V=5\times10^{4}$ 时，目标分布给正确词 $0.9$，给其余每个词 $0.1/50000=2\times10^{-6}$。这个分布自身的熵是

$$H(p)=-0.9\ln0.9-49999\times2\times10^{-6}\ln(2\times10^{-6})$$

第一项 $0.9\times0.105=0.095$。第二项：$49999\times2\times10^{-6}=0.1$，$\ln(2\times10^{-6})=-13.12$，乘起来 $1.31$。合计 $1.41$ nat。

交叉熵的下界就是目标分布的熵，所以模型再好，损失也降不到 $1.41$ 以下。困惑度的地板从 $1$ 变成 $e^{1.41}=4.1$。**一个用 label smoothing 训出来的模型，报告 PPL 3 是不可能的，除非它把地板也骗过去了。**

第二个代价藏在 logit 差距里。最优解要求正确词的概率是错误词的 $0.9/2\times10^{-6}=4.5\times10^{5}$ 倍，对应 logit 差 $\ln(4.5\times10^{5})=13.0$。也就是说，模型被明确告知“你最多只能这么自信”。对于要判断“这个 token 是确定的还是可以采样出别的”的场景，这个上限是有害的。

它的用处也是真的。没有平滑时，模型被鼓励把正确词的概率推到 1，logit 差距趋于无穷；在有限数据上，这等于把训练集里的偶然共现当成铁律。平滑把目标本身设成一个“带不确定性的分布”，模型不需要走那么远就能达标，泛化因此好一点。原论文在 2017 年的翻译任务上报了约 0.4 BLEU。

所以它在大模型预训练里几乎绝迹，在判别式任务（图像分类、小的文本分类）里还在用。区别在于这两类任务的输出分布本来就不该是尖的，而语言模型的输出该是尖的——一个训练充分的语言模型在“今天天气真”后面确实非常确定。

### z-loss 的量级：一根很软的弹簧

z-loss 的形式是 $c(\log Z)^{2}$，$c\approx10^{-4}$。这个数很小，值得算一下它到底能拉住什么。

先看数值贡献。$\log Z=20$ 时，惩罚项是 $10^{-4}\times400=0.04$；同一步的交叉熵大约 2.3，占比 1.7%。$\log Z=100$ 时惩罚是 $1.0$，占比 30%。所以它在正常情况下几乎不动损失，只在 logit 整体漂移得很厉害时才介入。

再看梯度。对 $\log Z$ 求导得 $2c\log Z=2\times10^{-4}\log Z$。$\log Z=20$ 时是 $0.004$；而交叉熵对 logits 的梯度量级是 $q-1[y]$，典型值在 $0.1$ 到 $1$ 之间。所以 z-loss 的梯度大约是主损失的百分之一。

但它和主损失的梯度有一个本质区别：主损失对“整体平移”是不变的（所有 logit 加同一个常数，softmax 不变，交叉熵不变，梯度之和为零——所有分量加上同一份、方向互相抵消）。z-loss 恰好只对这个平移方向敏感。所以两者不冲突：主损失管形状，z-loss 管位置，像一根很软但一直拉着的弹簧。

这就是它的全部价值。没有它，logit 的整体位置是一个自由漂移的量，由初始化、优化器动量、混合精度舍入共同决定；漂到几百之后，$\exp$ 在半精度里上溢，训练在一个随机步数上出现 NaN。有了它，这个自由度被钉住。

同类补丁还有几个，值得一起认识，因为它们的思路一样：**不改建模，只改数值行为。**

| 补丁 | 钉住什么 | 常见取值 |
|---|---|---|
| z-loss | logit 整体位置 | $c=10^{-4}$ |
| 梯度裁剪 | 单步更新幅度 | 范数 1.0 |
| 输出层 soft-cap | logit 上界 | 30 |
| 注意力 logit 上限 | 分数上界 | 通过 QK-Norm |

第二行的裁剪在 RNN 那一章讨论过，作用相同：它不管模型学得对不对，只管单步别走太远。第三行是给 logits 加一个 $\tanh$ 型压缩，代价是模型再也给不出极端自信的预测。第四行是让 $q$、$k$ 先各自归一化，把点积的量级从结构上压住，比事后缩放更硬。

### 一张表：四个损失变体的取舍

语言模型的损失不是只有一种写法。四种常见的变体各解决一个问题，也都带着副作用。

| 变体 | 解决什么 | 副作用 | 用在哪 |
|---|---|---|---|
| 纯交叉熵 | 无（基线） | 鼓励极端自信 | 预训练默认 |
| label smoothing | 过拟合 | 抬高损失地板 | 小数据分类 |
| z-loss | logit 漂移 | 几乎无 | 大规模预训练 |
| 蒸馏（KL） | 迁移软标签 | 需要教师模型 | 压缩、对齐 |

第一行是基线。它的“鼓励极端自信”不是缺陷，语言模型本来就该在“今天天气真”后面非常确定。

第二行的问题在上一节算过：地板从 1 抬到 4.1。所以它在预训练里退场。

第三行是纯工程补丁，数学上不改变最优解，只把 logit 的整体位置钉住。它的成本几乎是零，这就是它被广泛采用的原因。

第四行换了一个目标：不再拟合 one-hot，而是拟合教师的分布。它保留的不只是“正确答案是谁”，还有“哪些错误答案也算合理”。这在压缩小模型时特别有效，因为软标签携带了类别之间的相似结构。

四者可以叠加，但要小心相互作用。label smoothing 加蒸馏会出现两个“软化源”，需要重新调温度；z-loss 加蒸馏几乎无冲突，因为一个管位置一个管形状。

选择的原则很简单：先确认你要解决的是“拟合得不够”（用更强的模型或更多数据）、“拟合过头”（用平滑或早停）、还是“数值不稳”（用 z-loss）。三个问题的药方不一样，混着吃会把症状盖住。

### 消融：把温度从 1 改到 0.5

困惑度算的是分布，采样用的是分布的形状。温度是一个只在推理时存在的旋钮，但它能说明“损失”和“输出”不是同一个东西。

温度 $\tau$ 的做法是把 logits 除以 $\tau$ 再 softmax：

$$p_v(\tau)=\frac{\exp(z_v/\tau)}{\sum_u\exp(z_u/\tau)}$$

$\tau=1$ 是模型本来的分布；$\tau<1$ 让分布更尖，$\tau>1$ 让它更平。

拿一个具体分布算：正确词的 logit 是 4.0，其余词的 logit 大致在 0 附近，词表 50000。$\tau=1$ 时正确词的概率是 $e^{4}/(e^{4}+49999)=54.6/50054=0.0011$——注意只有千分之一，因为候选太多；分布熵是 $\ln 50000-4=6.8$ nat。

$\tau=0.5$ 时 logits 翻倍，正确词变成 $e^{8}/(e^{8}+49999)=2981/52980=0.056$，概率涨 50 倍，熵降到 4.1 nat。分布明显变尖，但离“确定”还很远。

$\tau=0.1$ 时正确词的 logit 变成 40，$e^{40}$ 是 $2.4\times10^{17}$，概率 $0.9999$，等价于贪心解码。

| 温度 | 正确词概率 | 熵（nat） | 行为 |
|---|---|---|---|
| 1.0 | 0.0011 | 6.8 | 原分布 |
| 0.5 | 0.056 | 4.1 | 更保守 |
| 0.1 | 0.9999 | ≈0 | 近似贪心 |

这张表说明两件事。第一，语言模型的原始分布通常很平——词表五万时，即使正确答案的 logit 高出 4，概率也只有千分之一。所以“模型很确定”这种感觉，往往要靠温度或者 top-p 才显现出来。

第二，温度不改变训练目标。它不改变模型学到了什么，只改变你怎么读它。这也是为什么调温度不能弥补模型的缺陷：如果模型的分布本身是错的，把它变尖只会更自信地错。

一个相关的观测指标是校准。理想情况下，模型说“我有 80% 把握”的那些位置，实际正确率应该接近 80%。温度是唯一一个能系统调节校准的参数，而它不改变排序——所以“调温度提升准确率”这个说法只在 top-1 之外才有意义。**温度是校准工具，不是能力工具。**

### 失败：标签错了一位

有一个错误在代码里只有一个字符的差别，效果却是“训练特别好，上线一团糟”。

正确的对齐是：位置 $t$ 的输出预测 $x_{t+1}$。实现里通常写成输入 `x[:, :-1]`、标签 `x[:, 1:]`。如果写成标签 `x[:, :-1]`，模型的任务就变成了“复述当前 token”。

损失会掉到 0.1 以下，因为任务太简单——输入里就有答案。曲线漂亮得不像话，任何人看到都会以为训练很成功。上线之后模型只会重复输入，因为它学到的是复制。

这个错误有两个变体，都同样静默。

一个是掩码没有配平。输入截成 $T-1$ 个，掩码却按 $T$ 生成，于是每个位置看到的内容和标签之间错开一位；损失不会异常低，只是收敛得慢，而且永远到不了应有的水平。

另一个是分词器的处理。如果训练时在句末加了 `<eos>`，而推理时的 prompt 没有，模型学到的“在 `<eos>` 之后开始新文档”这件事就用不上。反过来，如果推理时加了 `<eos>` 但训练时没加，模型会把 `<eos>` 当成普通 token 处理。两种情况的症状都是“生成内容对，但边界行为怪”。

自检的办法很土也很有效：把模型在一个 batch 上的预测打出来，看它给的 top-1 是不是输入的下一个 token。如果 top-1 等于当前位置的输入，标签就错位了。这一行检查应该写在第一次跑通训练循环的时候。

### 失败：损失在降，能力在退

损失是一个只往前看的指标：它衡量“在给定的前缀上，下一个词猜得准不准”。这个指标可以在模型真实能力不变甚至变差的情况下继续下降。

机制有三种。

第一种是重复数据。一份语料里有 30% 的样本是重复的，等价于把有效 epoch 从 1 提到 1.4。模型对这些样本的记忆加深，训练损失继续降；但它们在语义上和别的样本没什么不同，学到的增量几乎全是记忆。检测办法很土：在去重后的 held-out 上评估，两条曲线的分叉就是过拟合的量。

第二种是模板化。如果微调数据里 80% 的问句都是同一个句式，模型会把这个句式的回答学到极准，损失降得很快。上线之后用户换个问法，性能立刻掉。检测办法也简单：把验证集按“问句与训练集的最长公共子串长度”分组，看损失在不同组上的差距。

第三种是评测污染。训练语料里混进了评测集的原题，模型在训练中见过答案。损失当然降，评测分数也涨，涨得还很漂亮。这件事在大规模爬取的数据上很难完全避免，工程上的做法是 n-gram 级别的去重：把评测集的所有 13-gram 建一个哈希表，训练数据里命中任一条就丢弃。这个操作的成本很低，是被广泛采用的标准步骤。

三种机制有一个共同点：**它们都不改变模型在“没见过的输入”上的行为，只改变它在“见过的输入”上的行为。** 而训练损失恰恰是在“见过的输入”上算的。这就是为什么评估必须用独立的数据，而且必须是去重过的独立数据。

更细一层，损失下降的位置分布也有信息。如果下降全部来自最后 10% 的 token 位置（长文档的结尾），说明模型在拟合文档结尾的固定模式；如果下降集中在标点和虚词上，说明它在学格式而不是内容。把损失按位置、按 token 类型拆开看，比看一个总数有用得多。

到这里，一个训练步的完整链条就清楚了：前向算出 $T$ 份 logits，每份过一个 softmax，取正确词那一项的负对数，平均成一个标量，反向传播把梯度送到每个参数上。这个标量叫损失，它的指数叫困惑度，它衡量的是模型给正确词分配了多少概率。

但这条链上还差一环。前面几章分别拆了注意力、多头、位置、损失，每一块都单独说得通，却不保证拼起来能跑。一次完整的前向到底长什么样，形状在哪里对齐、在哪里变形、一个 batch 的数据从进去到出来经过了多少次矩阵乘——下一章把这些零件装成一个能跑的小模型，一行一行走完。
