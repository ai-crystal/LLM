## 质量与配比：分类器、DoReMi、退火

有一段文本，能通过前面所有关卡的检查。长度八百词，落在 50 到 10 万之间；平均词长 4.7 个字符，在 3 到 10 之间；含字母的词占 96%，过线；没有重复行，没有脏词，语言识别给英文的概率 0.99。它甚至不重复——全网独一份，是某个商家为自己产品写的介绍。

内容是这样的：这款收纳盒采用优质材料，做工精细，设计贴心，容量充足，适合各种场景，是你居家旅行的理想选择。接下来它把这套话换十二种说法又说了一遍，中间插了三个“限时优惠”。

规则抓不住它，因为所有规则问的都是“这段文字像不像自然语言”。它完全像，它只是不值得学。要把“像”和“值得”分开，得先有一个关于“好”的判据，而“好”没法写成阈值——百科条目、数学讲义、技术博客、论坛里的高质量回答，它们的共同点不在字符统计上，在“读完能学到东西”这个模糊的性质里。

能表达模糊性质的东西只有模型。于是流水线里多了一道：训一个分类器，让它给每篇文档打一个分，按分裁剪。这道工序看起来只是把阈值从人手里交给模型，实际上它决定的事比阈值重得多——它定义了模型眼中的“好文章”是什么样，而模型会朝着这个定义长大。

### fastText：几分钟训完的分类器

GPT-3 的做法是这条线上最早的公开样本。正例取 Wikipedia、WebText2、Books1、Books2 这些已经人工筛过的文本，负例取同一时段未过滤的 Common Crawl 随机抽样。训练用的模型是 fastText，一个刻意做得极简的文本分类器。

它的输入是一篇文档的词袋加上 bigram：把每个词和每个相邻词对映射成一个整数特征 id，全部装进一个向量，词频作为该维的值。这个向量极其稀疏——文档平均几百个词，特征空间却有上百万维。为了不让哈希表爆掉，实现上把所有特征哈希到固定数量的桶里，比如 $2^{21}$ 个，碰撞可以接受，因为分类任务本来只需要粗粒度的信号。

模型本体是一个线性层加 softmax：给定特征向量 $x\in\mathbb{R}^{d}$，第 $c$ 类的得分是

$$s_c=w_c^{\top}x+b_c,\qquad p(c\mid x)=\frac{\exp(s_c)}{\sum_{c'}\exp(s_{c'})}$$

$w_c$ 是第 $c$ 类的权重向量，$b_c$ 是偏置，$d$ 是哈希后的特征维度。标签只有两个（好、坏），所以 $c$ 取两个值，$w_1-w_0$ 就是一条把“好文档”和“坏文档”分开的超平面。白话：它算的是“这篇文档里出现的词，平均而言更常出现在好文章还是坏文章里”，加权求和，过一遍 softmax。

训练就是对这个目标做几轮随机梯度下降。因为模型只有一层、特征已经哈希好、softmax 只有两类，整个过程在 CPU 上跑几分钟到几十分钟就能收敛；打分时每篇文档只需要把特征加一遍再乘一个向量，单核每秒几十万到上百万篇。这两个数字是它被选中的全部理由——后面要做的是给几万亿 token 打分，分类器本身的推理成本必须低到可以忽略。

分数出来之后怎么用，比分类器怎么训更影响结果。GPT-3 没有设一个全局阈值，而是按来源分别定分位点：Wikipedia 这类来源几乎全收，Common Crawl 只留得分最高的百分之十几。原因是不同来源的分数分布根本不在一个位置上——同一个模型给论坛帖子的分数天然低于给百科条目，用一条全局线去切，等于把整个体裁一刀砍掉。按来源取分位点，等于说“每个来源保留它自己最好的一部分”，体裁的多样性因此得以保留，代价是每个来源里被保留的那部分质量参差。

Common Crawl 抽取出的文本压缩后是 45TB，这套过滤之后剩下 570GB，再按配比混进其他来源，最终参与训练的是 3000 亿 token。The Pile 把这个模子改了一处：正例只用 OpenWebText2（Reddit 上被点赞的外链），不用整个 Pile。论文附录里解释了原因——把 Pile 全部当正例，等于告诉分类器“这些都算好”，而 Pile 里本就混着大量普通网页文本，正负例的边界因此糊掉，分类器的区分度反而下降。

这两处改动的差别说明了一件事：正例选什么，分类器就学什么。选书籍与百科，学到的是“书面、结构清晰、少口语”；选 Reddit 外链，学到的是“人觉得有意思”。前者会把对话和口语判成低质，后者会把百科判成“没人看”。没有中立的选项，只有明确的选择。

### 让大模型当老师：教育价值分类器

fastText 的上限不在模型，在标签。“好”这个标签本身太粗，它把百科、教材、深度报道、优质博客压成同一个正类，分类器只能学到它们最表面的共同点：句子长、少缩写、段落有主题句。学到最后，它成了一个“像不像维基百科”的检测器。

FineWeb-Edu 换了一种问法：不问“这篇好不好”，问“这篇有多少教育价值”。问法一变，标注就可以做得更细——0 到 5 分，每一分对应一组可判断的特征。

标注的做法值得完整看一遍，因为它是所有“模型打标 + 小模型蒸馏”流水线的模板。从 FineWeb 某个快照里随机抽 46 万个网页，每一个都送进 Llama-3-70B-Instruct，用一段精心写的提示词要求它打 0 到 5 分。提示词的设计有三处细节：逐条加分（满足一条加一分）而不是从五档里选一档，这样标注的方差小；明确要求“关注中小学水平的知识”，这一句是为了防止模型把所有 arXiv 摘要都打成 5 分——学术文本的信息密度高，但它不是“教育价值”高的文本；要求先给理由再给总分，输出格式固定为 `Educational score: <n>`，方便用正则抽数字。

46 万条标注分成 41 万训练、5 万验证。真正拿去给 15 万亿 token 打分的东西不是那个 70B 模型——它跑不起——而是一个蒸馏出来的小分类器：拿一个现成的句向量模型（Snowflake-arctic-embed-m）当编码器，权重全部冻结，只在它的输出向量上训一个线性回归头，20 个 epoch，学习率 $3\times10^{-4}$，输出四舍五入到 0 到 5，按验证集 F1 挑 checkpoint，最后 F1 是 82%。

82% 这个数字决定了一切。按 F1 82% 的验证表现，大约每五篇文档里就有一篇的判断和老师对不上，而这条流水线要把这个判断应用到 15 万亿 token 上。按这个比例算，被误判的 token 是万亿量级。误差还不是随机的：老师是同一个模型、提示词是同一段、编码器是同一个，它的偏好在整个语料上高度一致，所以错的方向也一致——整类文本被系统性地抬高或压低，而不是随机噪声互相抵消。

阈值取在哪，得到一个不同的语料。取 3 分以上，剩下 1.3 万亿 token；取 4 分以上，只剩不到四成。前者是在 MMLU/ARC 的收益和 HellaSwag 的损失之间折中的结果：MMLU 从 33% 涨到 37%，ARC 从 46% 涨到 57%，HellaSwag 掉了几个点——它考的是日常情境的常识续写，而“教育价值”高的文本里恰好很少有这种东西。把分类器跑遍 15 万亿 token 花了 6000 H100 小时，相当于把一个小模型的训练算力花在了打标上；它只需跑一次，而且能和其他阶段并行，这是这类过滤能落地的前提。

最刺眼的对比是：用 1.3 万亿 token 训出来的模型，打赢了用 15 万亿 token 训出来的那个。十分之一的数据，更好的结果。这条结论后来被反复引用，但它成立有条件——那 1.3 万亿是从同一批网页里挑出来的，体裁分布被刻意保住了一部分；如果只追求分数、把阈值提到 4 分以上，剩下的就只剩教科书式的说明文，模型会变得很会解释、不会聊天。

### 分类器在奖励什么

把任何一个质量分类器打开看，它奖励的东西都很具体：清晰的主题句、明确的段落结构、解释性的连接词、术语的统一定义、没有口语填充词。这些特征在百科、教材、技术文档里密集出现，在对话、小说、论坛、代码注释里稀疏。

于是过滤的偏向可以预测：它会压低对话与口语（“嗯”“那个”“你懂的”是噪声），压低第一人称叙事（“我昨天去了”没有信息密度），压低代码（缩进和符号在词袋里是怪东西），压低非英语（分类器的训练样本几乎全是英文，其他语言在它眼里天然是低分）。这四类恰好都是模型能力的一部分。一个只会写教科书的模型，在客服场景、在角色扮演、在需要读懂一段报错日志的时候，会立刻露馅。

量化这个偏向有一个简单办法：按来源统计被保留的比例。被 3 分阈值保留下来的文档中，教育类站点的占比远高于它们在原始语料里的份额，而论坛、博客、电商被压到很小。这不是 bug，是分类器在忠实地执行“教育价值”这个定义。问题在于这个定义是别人（写提示词的人）定的，而它的后果由整个模型承担。

还有一层更隐蔽的风险：反馈回路。分类器的训练样本是“人认为好”的文本，它的输出决定模型看什么，模型又会影响下一轮数据的选择——用模型生成的数据做训练、用模型给数据打分、再用打分结果去训练下一个模型。一旦某个表面特征恰好和高分相关（比如段落里出现“总的来说”），生成这类文本的网页就会成批被保留，语料随之漂移，而这个漂移在单个 checkpoint 的评测里看不出来，只在几代模型之后显形。

工程上的对策不是“不用分类器”，而是给它装几个约束。

第一个约束是配比上限。高质量那一档通常只占总量的一半上下，剩下的一半留给低分但多样的部分：多语言、对话、代码、长尾站点。这个比例没有理论依据，来自实验——纯高分配比的模型在知识类评测上更好，在对话和指令跟随上更差。

第二个约束是分位数而不是绝对阈值。同一批数据里按分数排序，取前 $p$ 比例，$p$ 由 token 预算决定，而不是先定一个分数再看到底剩多少。这样做的好处是预算可控：要 3 万亿 token，就调到刚好剩下 3 万亿。

第三个约束是每种语言、每个来源各自定阈值。用一个英文分类器给中文打分，结果一定是中文整体偏低——不是因为中文质量差，是因为分类器没见过中文的“好文章”长什么样。多语言语料的做法是每种语言单独标几千条、单独训一个头。

第四个约束是留出评测集来监控偏向。除了下游任务分数，还要看被保留语料的体裁分布、语言分布、平均句长，以及模型在“非教育类”任务上的表现。这些指标不进主榜，但它们是唯一能提前发现语料漂移的信号。

::: {.keypoint}
质量过滤不是清洗，是一次关于“什么值得学”的投票，而投票结果会写进模型的能力结构里。任何单一判据用到极处都会收窄语料，所以真正的工程问题不是“怎么把分打准”，而是“在给定预算下，把多大比例留给不被判据偏爱的部分”。
:::

### 配比：每个领域放多少

过滤决定“留哪些”，配比决定“各留多少”。这两件事经常被混为一谈，但它们的自由度完全不同：过滤是逐篇的二值判断，配比是一组和为 1 的权重。

The Pile 是最早把这组权重写明白的公开语料。22 个子集，网页、论文、代码、书、百科、专利、邮件列表、问答、法律文书各占一块，比例是人工定的，论文自己也承认没有系统方法。它给出的理由是“覆盖体裁”：模型需要见过足够多种写法，才能在各种输入上都不至于手足无措。

手工权重很快遇到天花板，因为语料规模和领域数都在涨。一个半自动的做法是温度采样：设第 $i$ 个来源在原始数据里有 $n_i$ 个 token，采样时给它的概率取

$$p_i=\frac{n_i^{\alpha}}{\sum_{j}n_j^{\alpha}}$$

$\alpha$ 是温度参数。$\alpha=1$ 时按自然量采样，谁多谁是主力；$\alpha<1$ 时把分布压平，小领域被抬起来；$\alpha>1$ 时反过来，放大头部。白话：$\alpha$ 就是把“按数量分配”和“按数量开根号分配”之间连续调节的旋钮，常用的取值在 0.7 附近。

为什么是 0.7 而不是 1？因为自然分布被爬虫的抓取偏好扭曲了。原始网页里九成是商业页面和导航页，如果按自然量采样，模型见到的大部分 token 都在学“商品详情页长什么样”。压平一点，等于人为地把稀有体裁的曝光率提上来。代价是头部被欠采样：同样 15 万亿 token 的预算，$\alpha=0.7$ 时网页的占比从九成左右降到三分之二，省下的预算分给了本来只有几百亿 token 的领域。

难点在评估。给定一组权重，好不好只能训一个模型看结果；权重有 $k$ 个维度，$k=20$ 时网格搜索就不可行了。《Data Mixing Laws》(2024) 试图把这件事变成拟合问题：把验证损失写成各领域权重的函数，用一组小规模实验拟合出一组参数，再外推到没试过的配比。它的形式大致是指数型的——某个领域的权重从 0.1 加到 0.3，损失按指数下降然后饱和——所以拟合出来的曲线能表达“边际收益递减”，这正是网格搜索看不见的东西。

即便有拟合，配比仍然是一个随训练进程变化的东西。训练早期，模型需要的是让梯度保持多样性的内容；训练后期，它需要的是能提升特定能力的稠密内容。用一组固定权重从头跑到尾是省事的做法，也是次优的做法。

### DoReMi：用 2.8 亿替 80 亿试错

配比实验贵在每次评估都要训模型。在 80 亿参数上试二十组权重，等于二十次完整训练，这个开销没人付得起。《DoReMi》(2023) 的赌注是：可以在 2.8 亿参数上把权重搜出来，然后直接拿去训 80 亿。

方法是分布鲁棒优化（Group Distributionally Robust Optimization，Group DRO）的一个变体。设领域有 $k$ 个，$\theta$ 是模型参数，$\ell_i(\theta)$ 是模型在第 $i$ 个领域上的平均损失，$\ell_i^{\text{ref}}$ 是一个参照模型在同一领域、同一批数据上的损失。优化的目标是

$$\min_{\theta}\ \max_{w\in\Delta}\ \sum_{i=1}^{k} w_i\big(\ell_i(\theta)-\ell_i^{\text{ref}}\big)$$

$\Delta=\{w:w_i\ge0,\ \sum_i w_i=1\}$ 是所有合法权重构成的单纯形，也就是“一组加起来等于 1 的非负权重”。括号里那一项叫超额损失：不是“这个领域有多难”，而是“这个领域比参照模型差多少”。白话：外层在找最难对付的权重分配，内层在改进模型让它在这种分配下也别太差；两边轮流优化，最后得到的权重就是“当前模型最该补的短板”。

内层的模型更新就是普通的梯度下降，只是每个 batch 的样本按 $w$ 加权采样。外层的权重按对偶上升更新：

$$w_i^{(t+1)}\ \propto\ w_i^{(t)}\exp\!\big(\eta\,(\ell_i(\theta_t)-\ell_i^{\text{ref}})\big)$$

$\eta$ 是权重的学习率，$t$ 是步数。白话：某个领域的超额损失是正的（比参照差），它的权重就乘上一个大于 1 的因子；超额损失是负的（比参照还好），权重就缩水。跑几千步之后，权重会稳定在“每个领域的差距都差不多大”的位置——这正是 DRO 想要的均衡。

参照模型是用自然分布训出来的同规模模型，它的作用是消除“这个领域本身难”的干扰。没有它，权重会偏向那些天然困惑度高的领域（比如代码、数学），因为它们的损失永远比散文高。减去参照之后，比较的才是“改进空间”。

论文的规模是：2.8 亿参数、Pile 的 22 个子集，先训一个参照模型，再用 Group DRO 训一个代理模型，拿代理模型最后收敛的权重去训 80 亿的模型。结果是在 Pile 上的平均少样本准确率提升 6.5 个百分点；达到基线同等效果所需的训练步数只有基线的 $1/2.6$，也就是省了六成的算力。

这套方法的可迁移性建立在一个经验观察上：领域之间的相对难度，在小模型和大模型上排序相似。小模型学不好的领域，大模型同样吃亏；小模型觉得已经够了的领域，大模型也差不多了。这个观察在多数情况下成立，但它有明确的失效边界。

第一条边界是容量不匹配。2.8 亿的模型学不会需要长程推理的东西，它对“对话数据有没有用”的判断基本是噪声，于是权重会偏向那些“小模型容易记住”的领域——百科条目、代码片段、格式规整的问答。这些权重搬到 80 亿模型上，仍然有效果，但提升的部分主要是知识密度，不是推理。第二条边界是粒度：DRO 作用在领域这一层，域内的质量差异它完全看不到，一个“领域”里混着好文章和垃圾，权重只能整体抬高或压低。第三条是最实际的：它需要额外训两个 2.8 亿的模型，其中参照模型必须用同一份数据、同样的步数，否则超额损失不可比。

还有一条更省事的替代路线值得知道：不调权重，调数据本身。把每个领域按质量分成几档，只保留高档，然后按自然量采样。这在效果上接近“提高高质量领域的权重”，但它改变的是分布的支撑集，而不是权重，所以不会出现“某个领域权重被压到接近 0、模型彻底没见过它”的情况。两条路线经常一起用：DRO 定领域权重，质量分档定域内取舍。

### 打分一次要多少钱：两种量级

fastText 与 70B 教师之间的差距，在成本上不是十倍，是一千倍。两边都算一遍（口径：单快照 2.2 亿篇，每篇 300 词）。

fastText 的前向是“把特征加一遍再乘一个矩阵”：300 个词 × 2（词加 bigram 平均 600 个特征）× 2 个类 → 2400 次乘加，加上哈希开销，实际每篇约 $10^{4}$ 次操作。单核每秒按一万篇（含读盘与分词）算：

$$\frac{2.2\times10^{8}}{10^{4}}=2.2\times10^{4}\ \text{核秒}\approx 6\ \text{核小时}$$

六个核小时，按云计算一小时几美分。同一件事交给 70B 教师，上一章算过，是十七万卡小时、三十五万美元。

差四个数量级，但两者的产出不是同一种东西。fastText 学的是“词表里哪些词更常在正例里出现”，它能抓的是词汇层面的信号：脏词、口语填充、表格符号、乱码。70B 教师学的是“这整段话在讲什么”，它能抓的是语义层面的信号：是不是在解释一个概念、是不是在堆砌形容词。前者便宜到可以无脑全量跑，后者贵到必须蒸馏。

所以实际流水线是两层：fastText 先去掉明显不合格的一半，教师只在剩下的一半上抽样标注几万条，蒸馏出小模型，小模型扫全量。每层都只做自己便宜的那部分判断。这也是几乎所有数据工程的形状：便宜的分类器做漏斗，贵的模型做刻度。

### 82% F1 在 15 万亿 token 上意味着什么

82% 这个数字单独看没什么感觉。把它展开成一个混淆矩阵，代价就清楚了。

设真实高质文档占比 8.7%（对应最后保留 1.3 万亿 / 15 万亿），分类器的召回 0.85、精确率 0.80，两项合起来 F1 是

$$F_1=\frac{2\times0.85\times0.80}{0.85+0.80}=0.824$$

把 15 万亿 token 按这四个格子分开。

| | 判为高质 | 判为低质 |
|---|---|---|
| 真是高质 | 1.11 万亿 | 0.20 万亿 |
| 真是低质 | 0.28 万亿 | 13.41 万亿 |

保留下来的是 1.39 万亿，其中 0.28 万亿是误判进来的——占两成。每五篇被留下的文档里，有一篇其实不值得学；这个比例比“F1 82%”这个数字直观得多。

误删的那 0.20 万亿也值得看。它们是高质但被判低质的文档，而判低质的原因往往不是质量，是形式：一段没有小标题的深度分析、一篇带大量公式的讲义、一份全是图的报告。这些恰好是分类器训练集里少见的形式。所以误删不是随机的，它删掉的是“高质量但不典型”的文本。

两个方向的误差不对称。误判进来的低质文档会被模型当作正例学，影响是“学到一些垃圾”；误删的高质文档则直接不存在，影响是“永远学不到”。后者更难发现，因为它在损失曲线上没有痕迹——没见过的数据不会抬高损失。

这也解释了为什么阈值不是越高越好。把阈值抬高，精确率上去、召回下来，误判少了，误删多了。FineWeb-Edu 从 3 分提到 4 分，保留量从 1.3 万亿掉到不足四成，降的那部分里既有垃圾，也有大量“好但不典型”的文本。

### α=0.7 到底改变了什么

温度采样的效果可以手算。拿五个领域的自然 token 量（网页 $9\times10^{12}$、代码 $8\times10^{11}$、书 $2\times10^{11}$、论文 $1\times10^{11}$、百科 $5\times10^{10}$），分别在 $\alpha=1$ 和 $\alpha=0.7$ 下算占比：

| 领域 | 自然量 | $\alpha=1$ | $\alpha=0.7$ |
|---|---|---|---|
| 网页 | $9.0\times10^{12}$ | 88.7% | 75.6% |
| 代码 | $8.0\times10^{11}$ | 7.9% | 13.9% |
| 书 | $2.0\times10^{11}$ | 2.0% | 5.3% |
| 论文 | $1.0\times10^{11}$ | 1.0% | 3.2% |
| 百科 | $5.0\times10^{10}$ | 0.5% | 2.0% |

算一行就明白：百科的权重是 $(n_i)^{0.7}$，归一化后从 0.5% 抬到 2.0%，四倍。网页从 88.7% 压到 75.6%，让出的十三点全给了小领域。

这四个点不是免费的。$\alpha=0.7$ 意味着每读四个网页 token 就有一个被换成了别的东西，而网页是“世界知识”的主要载体。所以 $\alpha$ 的调整必须和下游评测一起看：知识类基准掉分，说明压得太狠；代码与数学没起色，说明抬得不够。

退火段的账也能这么算。总预算 10 万亿 token，退火占 5%，就是 5000 亿。这 5000 亿花在退火上的机会成本，等于“少训 5% 的主配方”，用幂律估：

$$\Delta L\approx0.095\times\ln(1.05)=0.0046$$

即少训 5% 只能换来 0.005 nats，而退火配方带来的差异通常比这大一个量级。这就是为什么退火段不能省：它不是“多训一点”，是“在最贵的窗口里换一批数据”。

### 同一个分类器，两种用法

质量分数不只可以用来“删”，还可以用来“排”。两种用法的差别比看上去大。

硬过滤是把分数低于阈值的文档直接丢掉，输出是一份更小的语料。它的优点是简单、预算可控；缺点是丢掉的内容永远不会回来，而分类器的误判是系统性的（前面算过，F1 82% 意味着保留的每五篇里有一篇不该要，而丢掉的每五篇里也有一篇不该丢）。

排序式用法是把分数当成采样权重：训练前期按分数排序取中间一段（保证多样性），后期逐步向高分端收紧，最后 5% 的退火阶段只用最高分的部分。这样做的效果是把“是否保留”变成一个连续旋钮，而不是一刀切。

两种用法的成本几乎一样（都要先打分），但代价结构不同。硬过滤的代价是“永久丢失”，排序的代价是“前期花了算力在低分文本上”。后者更安全，因为它保留了纠错空间：如果后来发现阈值定错了，改一行采样代码就行；而硬过滤需要从原始语料重跑。

这也是为什么 2024 年以后的数据流水线普遍把“打分”与“选取”拆开：先给全量数据打上分数与标签，存成一张表；训练时写一条查询决定取哪些。改决策不重跑流水线，这是 Dolma 那套“标注与过滤分离”的直接后果。

### 配比实验的三个坑

第一个坑是拿总损失做判断。前面算过，中文占比从 5% 提到 15%，总损失会涨 0.03，而模型一个字也没变差。正确做法是看分域损失加下游：中文域损失降了、英文没升，就是赚了。

第二个坑是代理模型的规模不匹配。DoReMi 在 2.8 亿上搜权重再拿到 80 亿上用，这条路的隐含假设是“领域之间的相对难度排序不随规模变”。它多数时候成立，但在两类情况下失效：一是需要长程推理的领域（小模型根本不会，因此低估它的价值），二是数据量极小的领域（小模型上的损失曲线噪声大到无法排序）。遇到这两类，要么把代理模型放大到十亿量级，要么直接给那类数据一个下限配额。

第三个坑是配比与学习率耦合。同样一份配比，学习率不同，最优权重也不同：学习率大时，模型更倾向于从“容易的领域”拿到快速下降，因为大步骤会放大易学样本的贡献；学习率小时，难领域才有机会。所以“在 A 学习率下搜出的最优配比”搬到 B 学习率上未必最优。工程上的做法是把配比与学习率一起搜，或者先定学习率（用一个小规模扫描）再搜配比。

三个坑的共同点是“一个变量单独调”。配比不是独立参数，它与数据质量、学习率、训练阶段强耦合；把它当独立旋钮，得到的结论只能在自己那套设置下成立。

### 退火：最后百分之几的 token 最贵

训练的最后阶段有一个特殊的窗口。学习率按余弦曲线衰减，走到末尾时接近 0，此时参数每一步只挪极小的一点，梯度的噪声也被这个极小的步长压住。模型在这个窗口里对数据分布最敏感——它已经学不动新结构了，只能把最后看到的东西“固化”进权重。

这件事被业界做成了一个明确的阶段，叫退火（annealing），或者衰减阶段。做法是把训练切成两段：前 90% 到 95% 用主配方，正常的学习率衰减；最后 5% 到 10% 换成一份精心准备的“好料”——高质量网页、教材式文本、数学与代码、指令数据、多语言的高质量部分，同时把学习率线性或按 $1-\sqrt{x}$ 的形状压到 0。

为什么有效，可以从两个角度看。从优化角度看，退火阶段的有效学习率极小，等价于在一个已经收敛的模型上做一次低步长的微调，模型只会往损失更低的方向做小幅度移动，不会破坏已经学到的结构。从数据角度看，这个阶段看到的每一条样本，其影响都被“放大”了——因为它出现在参数几乎不再变化的时刻，留下的痕迹不会被后续的梯度冲掉。所以同样一份高质量数据，放在训练中期掺进去，影响会被几万亿 token 稀释；放在退火阶段，影响保留得多。

数字上要给个量级感。假设总预算 10 万亿 token，退火占 5%，就是 5000 亿 token。这不是一个小数——它比大多数开源模型的全部训练数据都多。所以“退火数据”不是几百 GB 精选文本，而是几千亿 token 的高质量语料，要在训练开始前就准备好、清洗好、配比好。

退火配方里最关键的取舍是“稠密”和“不窄”的平衡。数据太宽（就是主配方），退火没有额外收益；数据太窄（只有数学题和代码），模型会在退火阶段丢掉对话能力和世界知识——因为学习率虽小，几千亿 token 也足够把分布改过去。常见做法是三层：一层是高质量通用网页（保住广度），一层是目标任务相关（数学、代码、指令），一层是多语言与长尾（防止英语独大）。三层的比例是退火阶段最重要的超参数，而它只能靠消融确定：训一个小的、用几种配比各跑一遍，看哪个在综合评测上不掉分。

这套机制还有一个副产品：检查点复用。因为学习率衰减的形状可以事后接上（WSD 调度，warmup-stable-decay），训练可以在 stable 阶段停在一个检查点，之后从那里接一段新的衰减，用新的数据配方做退火。这意味着一份底座可以退火出多个版本——一个偏代码、一个偏多语言、一个偏对话——而不必从头再训。MiniCPM (2024) 用这套调度训 2.4B 模型，把退火阶段单独拿出来做实验，报告说衰减阶段的数据配方对最终分数的影响，大于它在 token 总量里占的比例所能解释的。

风险也很集中。第一，退火阶段是单向的：配错了，前面几万亿 token 的投入没有回退路径，只能从 stable 阶段的检查点重来，而那个检查点可能已经被覆盖了。第二，退火数据量小，容易过拟合到具体来源，模型在退火数据覆盖的评测上分数飙升，实际使用中并没有变好。第三，退火阶段做的事和后训练（SFT）有重叠，如果退火里塞了太多指令数据，后面的 SFT 会因为“已经学过”而收益变小，两段的数据设计得一起看。

到这里，语料在磁盘上是一堆 UTF-8 文本：去过重、去过污染、按质量裁剪过、按领域配好权重，最后一段还专门留了高分配比。这些决定都已经写死，训练开始后改不了。接下来是另一件同样写死、同样改不了的事——把文本变成整数序列。同一段中文，换一个分词器，可能是 800 个 token，也可能是 1600 个，而训练预算、上下文能装多少内容、模型在算术上犯不犯低级错误，全都跟着这个数字走。
