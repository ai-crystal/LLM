## 预训练到底在学什么

一块 64 卡的机器跑到第 40 万步，日志最后一行是 `loss 2.071`。再跑 10 万步，它变成 2.043。两个检查点摆在面前，要决定这次训练停在哪里：多花两周机时换 0.028，值不值。

0.028 看上去微不足道。换算一下：每 token 少 0.04 bit，乘上十五万亿 token 是 $6\times10^{11}$ bit，七十五 GB。两个检查点在“能预测多少东西”上差的不是一个舍入误差，是几部百科全书的体量。但这个体量花在哪里、值不值，得先弄清楚这个数字到底在度量什么。

2.07 是什么？它不是准确率，不对应任何一项具体能力，测试集上答对几道题跟它没有直接关系。它是一个平均对数概率的相反数，单位是 nats，第二卷给过定义：

$$\mathcal{L}(\theta)=-\frac{1}{N}\sum_{t=1}^{N}\ln p_\theta\big(x_t\mid x_{<t}\big)$$

$N$ 是这段文本的 token 数，$x_t$ 是第 $t$ 个位置上的真实 token，$x_{<t}$ 是它前面的全部 token，$p_\theta$ 是参数为 $\theta$ 的模型给这个 token 分配的概率。句子的意思很直白：逐个位置取出“模型给正确答案的概率”，取对数、取负、再平均。模型越相信语料里真正出现的那个词，这个数越小；完全瞎猜时它等于 $\ln V$，五万词表是 10.82——那正是训练日志第一行的值。

从 10.8 走到 2.0，中间发生了什么，是这一章要回答的。答案分三层：这个数是按什么加权的，它在信息论上等价于什么，以及不同区间里的下降分别对应模型学会了什么。

### 一个平均数掩盖了什么

这个平均数按 token 加权，不按“知识点”加权。把求和按 token 重新分组，可以看清楚权重落在哪里：

$$\mathcal{L}=\sum_{v=1}^{V}\pi_v\,\ell_v,\qquad \pi_v=\frac{\bigl|\{t:x_t=v\}\bigr|}{N},\qquad \ell_v=\frac{1}{\bigl|\{t:x_t=v\}\bigr|}\sum_{t:\,x_t=v}-\ln p_\theta\bigl(v\mid x_{<t}\bigr)$$

$v$ 是词表里的一个 token，$V$ 是词表大小；$\pi_v$ 是它在这段文本里占的出现比例，$\ell_v$ 是模型在所有“下一个词是 $v$”的位置上的平均损失。白话：总损失是各类位置的平均损失按出现次数加权，出现得多的 token 声音大。

一份英文网页语料里，前一千个 token 覆盖全部出现次数的三分之二上下：the、of、and、逗号、句号、`-ing`、`-ed`。剩下几万个 token 分另外三分之一。一个训到 2.0 的模型，账本大致是这样：出现超过一百万次的 token，平均损失 0.4 到 0.8；出现几千到几十万次的，落在 1.5 到 2.5；一年只在语料里出现几十次的人名、型号、地名，损失在 4 以上，也就是模型给它们的概率只有百分之一二。

2.0 因此应该读成“常见位置的成绩单”。它说明高频语法和常见搭配学得很好，完全不说明模型认不认识 1978 年世界杯决赛的两支球队。后者的损失再高，乘上 $\pi_v\approx10^{-8}$ 之后对总和的贡献可以忽略。

这个视角也解释了训练后期的收益曲线。2.071 到 2.043 这么难，是因为剩下的损失集中在低频位置，而那些位置的梯度占全部梯度的千分之几。继续训练不是没用，是边际收益落到了长尾上；而长尾的绝对体量很大——十五万亿 token 里，出现次数少于一百的 token 位置合起来有上千亿个。

边际收益的差距可以算出来。设验证集里 96% 的位置是高频桶、3.9% 是中频桶、0.1% 是低频桶，现在有两件事可做：把低频桶的平均损失从 6 降到 3，或者把高频桶从 0.6 降到 0.5。前者对总损失的贡献是 $0.001\times3=0.003$，后者是 $0.96\times0.1=0.096$，差三十二倍。任何按总损失来优化的过程，都会优先去做后面那件事。这不是模型的偏好，是目标函数写定的：低频位置就算全军覆没，账面上也看不见。

### 从 nats 到比特

nats 这个单位不方便跟别的东西比。换成比特，除以 $\ln 2=0.693$：

$$\mathcal{L}_{\text{b}}=\frac{\mathcal{L}}{\ln 2}$$

2.07 nats 是 2.99 bit。英文 BPE 平均每个 token 约四个字符，于是每字符约 0.75 bit。同一批网页用 gzip 压，每字符要 2.2 到 2.5 bit。模型好三倍。

跨分词器比较时必须换算到每字符或每字节，否则会得出荒唐结论：同一个模型配三万词表和十五万词表，per-token 损失能差 0.5 nats，纯粹因为后者切得细、每个 token 携带的信息少。这件事讲到词表时还会回来，它是很多“我们的模型损失更低”这类宣称里的水分所在。

把整个训练账算一遍。十五万亿 token、每 token 3 bit，总码长 $4.5\times10^{13}$ bit，约五点六 TB。语料原文按每 token 四字节估是六十 TB，gzip 之后约十七 TB。训出来的模型，七十亿参数、bf16 存，十四 GB。

十四 GB 装下六十 TB 的“理解”，压缩比四千比一，比 gzip 还小三个数量级。这个对比必须加一个限定：它是有损的。模型没法从这十四 GB 还原原文，它只留下了“让原文看起来不意外”的那部分结构。有损压缩的压缩比可以任意高，关键看丢了什么。语言模型丢掉逐字细节，留下可预测性，而可预测性恰好就是“会说这门语言”的机械定义。

### 要压得动就得猜得准

Shannon 在 1948 年给出了一条现在看仍然锋利的结论：一个概率为 $p$ 的符号，最优二进制码长是 $-\log_2 p$。高概率的符号用短码，低概率的用长码，算术编码可以把平均码长压到这个下界。

代进模型的语言：某个位置模型给真实 token 的概率是 0.9，这个 token 分到 0.15 bit；概率 0.01，分到 6.6 bit。一段文本的总码长就是逐 token 相加，正是上一节那个 $\mathcal{L}_{\text{b}}$。所以“训练一个损失 3 bit 的模型”和“造一个每 token 平均 3 bit 的压缩器”是同一件事的两种说法。

反过来说，想压低损失只有一条路：让预测分布接近真实分布。这句话不需要“理解”这个词撑场面，因为一个足够大的查找表也能压低训练集损失。

区分背和学的是验证集。训练集 0.5、验证集 2.5，说明模型在记句子；训练集 2.1、验证集 2.2，说明它学到的是能迁移的规律。两种情况的训练损失可能一样低，压缩的对象完全不同：前者压的是这份文件，后者压的是这门语言。预训练的所有工程细节——去重、清洗、配比、早停——追的都是后一件事。

泛化在这里有一个精确表述。模型把训练集压到 0.5 bit/字符不稀奇，任何文件都能被记住；它在一份从没见过的网页上压到 0.75 bit/字符，说明它带走了关于英文网页的先验。这个先验就是全部能力所在，后面的 SFT 和强化学习都只是在这个先验上做条件化。

损失还有一张熟悉的脸：困惑度（perplexity，PPL）。它就是损失的指数，

$$\mathrm{PPL}=\exp(\mathcal{L})$$

2.0 nats 对应 7.4。常见说法是“模型每个位置相当于在七个候选之间犹豫”，这句话只在候选等概率时准确；模型的分布是偏斜的，7.4 是几何平均意义下的等效候选数。它的用处是量级感：PPL 从 20 降到 7.4，意味着模型把“平均要用 4.3 bit 才能编码的 token”压到了 3 bit。两个模型比较时，PPL 的比值开平方大致等于每字符比特数的比值，口算够用。

这个数字还有一个很容易踩的坑：它对分词器和数据分布都很敏感，拿两个模型的 loss 直接比，结论大半是假的。分词器的影响能算清楚。同一个模型、同一段文本，三万词表把“unbelievable”切成三个 token，十五万词表切成两个，后者的每个 token 携带的信息少，per-token 损失就低。要把这层影响消掉，得除回原始字节数：

$$\text{bpb}=\frac{\mathcal{L}}{\ln 2}\cdot\frac{1}{B/N}$$

$B$ 是这段文本的 UTF-8 字节数，$N$ 是它的 token 数，$B/N$ 就是平均每个 token 对应几个字节。白话：把每 token 的比特数摊到字节上，分词器切得粗细就不影响了。这个指标叫每字节比特数（bits per byte，bpb），跨词表、跨语言比较都靠它。

中文是最容易被误读的例子。同一个模型，中文验证集上的 per-token 损失往往比英文高 0.2 到 0.3，因为一个汉字携带的信息多，一个 token 覆盖的语义也多。换算成 bpb 之后，这个差距会缩到 0.05 以内，剩下的部分才是“中文确实更难”的真实差距；不做这步换算，会把分词效率的差别当成语言能力的差别。

数据分布的影响更大。七亿参数的小模型在维基百科上能做到 2.0，在随机抓的网页上只能到 2.6，差的不是模型水平，是两种文本的可预测性不同——维基的句子结构规整、事实密集、少口语。所以论文里报 loss 必然同时给验证集的名字，两者是一体的。看到“我们的模型损失 1.9”而不说在哪份数据上，这个数就没有意义。

### 曲线的前半段：语法

损失下降并不均匀。横轴取 token 数、纵轴取损失，画在双对数坐标上，中后段接近一条直线（讲缩放定律时会回到这条直线的斜率），而开头那段陡得不像同一条曲线：10.8 到 4 通常在前百分之一的 token 内就走完了。

这一段学到的是局部规律。哪些词能相邻、冠词和名词怎么配、主谓怎么一致、句号后该大写、引号怎么成对。这些依赖跨度只有几个 token，每种组合在语料里出现几百万次，梯度信号密集，参数很快就能把它们拟合进去。3.0 附近的模型已经能写出语法上挑不出错的句子，代价是内容空洞：“随着经济的发展，人们的生活水平不断提高，这是一个值得关注的问题。”每个搭配都对，整句没有信息。

这里有个容易误判的现象。损失 3.5 的模型被问“法国的首都是哪里”，可能续出“法国的首都是法国”。这不是语法错误，也不是知识空白，是它在低损失区学到的最省事的模式：把主语重复一遍，在多数上下文里都安全。事实要另外一套参数去存，而存事实在损失上的即时收益很微弱。

局部规律之上还有一层。跨从句的主谓一致、代词指代、引号与括号的闭合、时态在整段里的统一，这些依赖跨度几十个 token，每种具体形式在语料里的出现次数比局部搭配低两个数量级。它们的损失在 3.0 以下才明显改善：2.5 附近的模型能写出语法正确、指代不乱的段落，但段落之间的推进还是散的，读起来像四句不相干的话拼在一起。连贯需要的是“上一段说了什么”这种全局状态，而全局状态在因果语言模型里只能靠上下文窗口里的注意力去重建，没有专门的参数去存。

### 曲线中段：事实进了参数

一个参数量为 $N$ 的模型能存多少事实？《Physics of Language Models: Part 3.3》(2024) 用合成传记数据给了一个可以复算的答案：约 2 bit 每参数。

$$\text{知识容量}\approx 2N\ \text{bit}$$

七十亿参数对应 $1.4\times10^{10}$ bit，一点七五 GB。英文维基百科正文约四十亿 token、十六 GB 纯文本，也就是说一个 70 亿参数模型的“事实硬盘”大约是维基的九分之一，而不是九倍。这个数字比多数人的直觉小得多，却和日常观察吻合：模型知道维基里的大部分常识，一落到人名、日期、数字这些最占容量的细节就频繁出错。

同一组实验还有一条结论：想把容量吃满，同一条事实要在训练里出现上百次。实践也印证了它——一个实体在语料里出现四五次，模型能“认得”，答得出大概；想让它稳定复述准确，得几十上百次。

这套算术还解释了幻觉的形状。空缺的位置上，模型不会输出“不知道”，因为“不知道”极少跟在“某球员的生日是”后面。它用结构相似的实体的模式去填：见过一百个球员的生日都以 19 开头，就给出一个同样形状的日期，格式对、语气对、数字错。错误因此总是“合理的”，这正是预训练目标的直接后果——它奖励“像语料里会出现的文本”，不奖励“与事实相符”。要求模型说“我不确定”，是在要求它偏离训练分布，这件事只能靠后训练来做。

而事实在损失里的权重极低。假设一个人名在十五万亿 token 里出现两百次，它占的份额是 $1.3\times10^{-9}$。模型在这个位置上错得再离谱，对总损失的影响也在小数点后第九位。

$$\frac{\partial\mathcal{L}}{\partial\theta}=\frac{1}{N}\sum_{t=1}^{N}\nabla_\theta\Bigl(-\ln p_\theta\bigl(x_t\mid x_{<t}\bigr)\Bigr)$$

每个位置的梯度都乘了同一个 $1/N$。白话：罕见事实的梯度被平均数稀释，优化器几乎感受不到它的存在。

工程上的对策都是人为把这个权重抬回来：把语料重复几遍、给高质量来源加权、对特定领域上采样。这些动作在损失曲线上几乎看不出来，在能力上差别很大——这也是为什么训练损失不能当模型好坏的指标用。

### 后半段：算法从分布里长出来

十亿 token 量级时，注意力里会长出一个特定的回路。两层配合：第一层把“当前 token 在前面出现过什么”编码成一个位置指针，第二层拿当前 token 去查这个指针，输出“上次它后面跟的那个 token”。《In-context Learning and Induction Heads》(2022) 把它叫作归纳头（induction head），并记下一个细节：它形成时，损失曲线上会出现一个小凸起，先变差再变好。

这个回路的意义超出它本身。它让“上下文里重复的模式”直接变成预测，而这是上下文学习（in-context learning）的机械基础：给模型三个“苹果→apple”的例子，它把第四个照做，靠的不是新知识，是这条“找重复、抄后面”的回路。

算术和多步推理的痕迹更零散。三位数加法在损失上分成几级台阶：先学会个位不进位的直加，再学会进位，再学会连续进位。每一级都不是被单独教的，是语料里“竖式题、口算题、错题讲解”这些文本排布被拟合之后自然出现的。模型不是先有算法再产生输出，它是先会输出，算法是输出里被压出来的中间结构。

多步计算之所以吃力，有一个纯概率的原因。设每一步算对的概率是 0.95，五步全对的概率是 $0.95^{5}=0.77$，十步只剩 0.60。模型在一次前向里把所有步都做完，误差就连乘；而人在纸上写竖式，每一步都可以被上一步的结果“扶正”。这解释了为什么让模型写出中间步骤会明显提升准确率：它把一次十步的隐式计算拆成十次一步的预测，每次预测都能看到前面已写下的数字，误差不再连乘。

思维链（chain of thought）在这里也该摆正位置。预训练没有教模型“思考”，它学的是“题目后面跟解题步骤、步骤后面跟答案”这种文本排布。推理时让模型先写步骤，等于把它推到训练分布里那个“正在解题”的区域，后续 token 的预测因此更准。这个能力第五卷会用强化学习放大，但种子在预训练语料里。

### 会什么，不会什么

把上面几段拼起来，能得到一张关于 base 模型的能力清单，而且每一项都能回溯到它的成因。

它会的：模仿文体。给两段公告，第三段公告的用词、句长、称谓都会跟上，这类规律在语料里重复了上亿次。格式转换，包括翻译、改写、抽取、润色，因为“同一内容的不同写法”在双语网页、摘要、问答站里大量并列存在。常识，因为常识就是高频共现：杯子、热水、烫手；下雨、雨伞、忘带，这些搭配在十五万亿 token 里被反复写过。代码，因为 GitHub 提供了几十种语言、数亿文件的平行样本，缩进、命名、报错修复的模式密集到足以被拟合。

它不会的：精确算术，因为结果需要逐步执行而不是模式匹配，而语料里“算式与答案”的配对密度远远不够。实时信息，因为参数在训练结束那一刻就冻住了。长程计划，因为它在训练里只见过别人写好的计划，没见过自己执行计划的过程。稳定的置信度，因为损失函数只奖励“像语料”，不奖励“知道自己不知道”。罕见事实，因为 2 bit 每参数的容量和 $1/N$ 的梯度权重都不允许。

这张清单的共同点：每一项的边界不在模型结构里，而在语料的形状里。换一份语料，清单就变了。一个以中文网页为主的模型，中文成语的掌握会好得出乎意料，代价是它在英文法律文本上的表现掉一截；一个代码占比高的模型，算术会莫名变好，因为代码里到处是数字与运算。这解释了为什么“模型能力”不是一个标量，也解释了为什么后面每一章都要回到数据。

### 会续写不等于会回答

给一个只做过预训练的模型（base 模型）输入“法国的首都是”，它会续写。可能续出“巴黎，人口 210 万，是法国最大的城市”，也可能续出“一个问题，这个问题困扰了我很久”，还可能续出“哪里？我不知道”。三种都不算错，因为它在建模“这段文本后面会接什么”，而互联网上这三种接法都存在。

对话模型的行为完全不同：它给出一个回答，只有一种语气。差别来自几万到几百万条（提问，回答）样本的监督微调（supervised fine-tuning，SFT）。

用概率的语言说，预训练学到的是 $p_\theta(y\mid\text{prompt})$ 的一个混合，成分是网页、论坛、小说、问答站、说明书里所有可能的续写方式；SFT 在这个混合上做条件化，把“助手口吻”那一支的概率抬到接近 1，其余压下去。

这个过程可以在采样里看到。同一个 base 模型，温度 0.7，跑十次“法国的首都是”，大约六次给出百科式续写，两次接成论坛提问，两次接成小说对话。换成 SFT 之后的模型，同温度下十次里九次是回答。混合没有消失，只是被推到了一个窄区域里——这就解释了 chat 模型为什么在长对话里偶尔“掉出角色”，开始替用户写下一句：那条支路的概率被压小了，没有归零，上下文一旦滑到它熟悉的区域，它就会滑回去。

数据量的对比值得记住：SFT 用几万到几百万条，预训练用十几万亿 token，差四到六个数量级。SFT 没教模型新知识，它教的是“在这个场合该用哪一种说法”。所以 base 模型缺的知识 SFT 补不上，base 模型没有的能力 SFT 也只能把它已有的东西挑出来。

一句话收束这一章：损失曲线描述的是模型对语料的压缩程度；压缩得好不好，取决于语料里有什么、出现多少次、以什么形式出现。一个只在新闻上训过的模型不会写代码，不是参数量不够，是它的语料里没有代码那种排布。

2.071 还是 2.043，这个决定最终不该只看 loss。但 loss 告诉你的是同一件事：模型还能从这批数据里榨出多少可预测性。榨不出更多的时候，换数据比加机时有用。下一章去数据那一端看——一个每月抓几十亿网页的爬虫，怎么就变成了一份能喂给模型的语料。
