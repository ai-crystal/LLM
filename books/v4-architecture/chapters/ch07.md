## 长上下文：位置、注意力、数据、评测

一份 300 页的并购合同，转成 token 大约 25 万。产品需求写得很干脆：把整份合同读进去，找出所有对赌条款，并且说明每一条的触发条件。看上去这只是一次 API 调用，参数里填 `max_tokens=256000`，按 token 付费。

真正跑一遍会发现四个地方同时出问题。模型在 25 万 token 的位置上找不到任何东西，因为它训练时只见过 8K 的长度，位置编码在那个尺度上已经失真。请求排不进显存，因为 128K 上下文的 KV 缓存就要 40GB，而一张卡要同时挂十几个请求。就算硬塞进去了，答案也常常是"合同中没有相关条款"——把条款放在文档中段时，模型的表现比放在开头差一大截。第四处是账单：同一个请求，prefill 的算力是 4K 上下文版本的百倍上下，首 token 要等十几秒。

窗口长度是一个数字，可用长度是四件事叠起来的结果。这一章按这四件事拆开：位置编码怎么把没见过的长度折回训练区间，注意力怎么摊到多张卡上，缓存怎么压，数据与评测怎么定义"可用"。

### 先把账算清楚

从 4K 到 1M，长度涨 256 倍，账本上每一项的涨幅不同。

KV 缓存按 token 线性涨。每个 token 的缓存大小是

$$\text{KV}_{\text{token}}=2\times L\times H_{kv}\times d_{head}\times b$$

$L$ 是层数，$H_{kv}$ 是 KV 头数（分组查询注意力里它小于 query 头数），$d_{head}$ 是每头维度，$b$ 是每个元素的字节数，前面的 2 是 key 与 value 各一份。取一个 70B 级的配置：80 层、8 个 KV 头、每头 128 维、bf16 存储，每 token 是 $2\times80\times8\times128\times2=327{,}680$ 字节，约 320KB。

乘上长度就是单请求的缓存：4K 是 1.3GB，128K 是 40GB，1M 是 320GB。再看并发。70B 的 bf16 权重是 140GB，八卡张量并行切开，每卡 17.5GB，80GB 的卡剩下约 62GB 装缓存；张量并行同时把 KV 头也切开，八卡各分到一个头，于是每卡的缓存是总量的八分之一。4K 时每卡 168MB，能挂三百多个请求；128K 时每卡 5GB，只能挂十二个；1M 时每卡 40GB，一个半。**长度每涨一个数量级，并发能力掉一个数量级**，这是长上下文服务最硬的一条约束，比算力更早撞墙。

注意力算力按长度平方涨。第 $t$ 个位置要对前面 $t$ 个位置打分，总对数是 $T(T+1)/2$，量级 $T^2$。这一项在小模型短上下文时可以忽略，到 128K 就反超权重计算，算成本时再给具体数字。

真正不随长度变的只有权重。参数量的账在长度维度上是常数，这也解释了为什么厂商愿意在长上下文上投入：能力是新的，权重不用重训。

### 位置：把没见过的长度折回训练区间

旋转位置编码（RoPE）把位置写进 query 和 key 的相位。第 $m$ 个位置的第 $i$ 对维度旋转 $m\theta_i$，角频率

$$\theta_i=\mathrm{base}^{-2i/d},\qquad i=0,1,\dots,\tfrac{d}{2}-1$$

$\mathrm{base}$ 是频率谱的底数，原论文取 10000；$d$ 是每头维度。两个位置的点积只依赖角度差 $(m-n)\theta_i$，相对位置因此是构造出来的，不用学。

每个维度有一圈的长度，叫波长 $\lambda_i=2\pi/\theta_i=2\pi\,\mathrm{base}^{2i/d}$。$i=0$ 时 $\lambda_0=2\pi\approx6.3$，也就是每 6 个 token 转一圈，负责分辨相邻位置；$i=d/2-1$ 时 $\lambda\approx2\pi\times10000\approx6.3$ 万，要六万个 token 才转完一圈，负责分辨"隔得很远"。整套频率谱覆盖了从 6 到 6 万 token 的尺度。

问题出在最大波长上。模型在 4K 上训练，意味着每个维度的相位只在一个有限的区间里出现过；长度到了 128K，最慢的几个维度要转过 32 倍的角度，落进训练时从未出现的相位区域。点积的数值没坏，但它的含义坏了——模型没见过"隔了 12 万 token"长什么样。所有位置扩展方法都在做同一件事：**把新的长度折回训练时见过的相位区间**，区别只在折哪几个维度、折多少。

位置插值（Position Interpolation，PI）最直接，把所有位置除以扩展倍数 $s$：

$$m'=\frac{m}{s}$$

128K 除以 32 就回到 4K。代价一句话能说清：所有维度一起被压缩，相邻 token 的相位差变成原来的 $1/s$，模型对"第 8000 位和第 8001 位"的分辨能力被拉粗了 32 倍。补救办法是在长文本上做少量微调，论文报告约一千步就能恢复，比从头训长上下文便宜几个数量级。

NTK 感知的做法换个折法：不动位置，动底数。设扩展倍数 $s$，把底数改成

$$\mathrm{base}'=\mathrm{base}\cdot s^{\frac{d}{d-2}}$$

这个指数看起来突兀，代进去就清楚了。新的角频率是 $\theta_i'=\mathrm{base}'^{-2i/d}=\theta_i\cdot s^{-2i/(d-2)}$，于是第 $i$ 维的波长被拉伸了

$$\frac{\lambda_i'}{\lambda_i}=s^{\frac{2i}{d-2}}$$

$i=0$ 时拉伸倍数是 1，最高频维原封不动，近处的位置分辨率保住了；$i=d/2-1$ 时指数等于 $s^{(d-2)/(d-2)}=s$，最慢的维拉到 $s$ 倍，远处的相位不再重叠；中间的维度按 $i$ 线性过渡。一句话：**高频不动，低频拉长，中间按比例走**。这比 PI 精细，代价是需要重新标定底数，且不同维度被拉伸的比例不同，模型得适应一套不再等比的频率谱。

YaRN 把"中间按比例走"写成一条显式的斜坡。对每一维算一个比值

$$r_i=\frac{L_{\text{train}}}{\lambda_i}$$

$L_{\text{train}}$ 是训练长度。$r_i<1$ 说明这一维的波长比训练长度还短，在训练区间里转过好几圈，属于高频，一点不动；$r_i>1$ 说明波长超出训练长度，转不满一圈，属于低频，按 $1/s$ 全额插值；中间的一段线性过渡。插值之后的注意力分布会变平——角度差被压小，点积的取值范围收窄，softmax 输出的熵上升——所以 YaRN 在 logits 上乘一个温度因子补回来，温度取 $t=0.1\ln s+1$。三项加起来的效果是：达到同样质量所需的继续训练数据比此前方法少十倍，训练步数少 2.5 倍，只用了原预训练数据量的 0.1%。

LongRoPE 再往前一步，不靠公式给倍数，而是逐维搜索最优的缩放系数——不同维度的敏感度本来就不一样，统一公式只是近似。搜出来的方案把窗口推到 200 万 token 量级，之后再在原始长度上做一轮恢复训练，把被拉长的频率对短文本的影响收回来。这一步不能省：只做扩展，短文上的困惑度会退化。

逐维缩放的实现并不复杂，麻烦的是它必须和 kernel 一起写。下面这段是 YaRN 那种“分段斜坡”的最小实现，输入是维度号，输出是这一维的位置缩放系数：

```text
# base 是 RoPE 底数，s 是扩展倍数
# L_train 是训练长度，lo/hi 是斜坡的上下界
def dim_scale(dim, base, s, lo=1.0, hi=32.0):
    out = []
    for i in range(dim // 2):
        lam = 2 * pi * base ** (2 * i / dim)
        r = L_train / lam
        if r < lo:
            out.append(1.0)          # 高频不动
        elif r > hi:
            out.append(1.0 / s)      # 低频全插
        else:
            t = (r - lo) / (hi - lo)
            out.append(1.0 / (1 + t * (s - 1)))
    return out
```

六行逻辑里最容易出错的是两个分支的边界。$r<lo$ 全部不动，意味着最高频那一批维度的波长比训练长度还短——它们在训练时已经转过很多圈，不存在“没见过的相位”，所以不该动。$r>hi$ 全部插值，意味着这些维度在训练时连一圈都转不满，它们的绝对值就是“距离”本身。中间那段线性过渡，是因为这里没有理论依据，只能取一个连续的插值。

这里有一个必须提醒的实现细节：这个函数返回的是**逐维系数**，而 RoPE 在 kernel 里通常写成对相邻两维做一次旋转。若把系数写成了“整个张量一个标量”，它就退化成普通的位置插值，短文本上的分辨率会整体下降，而长文本也不见得好。这类错误跑一次短文本困惑度就能看出来，但很容易被当成“外推方法本身不行”。

工程上还有一条更朴素的路线：直接把底数调大。Llama-3 把 128K 上下文的底数设成 500000，Qwen3 设成 $10^6$，配 YaRN 与双块注意力做 4 倍推理扩展。底数变大等于把整条频率谱整体放缓，和 NTK 感知是同一个方向，只是不做逐维区分。

四条路放在一起，取舍其实只有三个参数：**动不动位置、动不动频率、要不要继续训**。

| 做法 | 改什么 | 继续训 | 主要代价 |
|---|---|---|---|
| 位置插值 | 位置除以 $s$ | 约千步微调 | 局部次序分辨率降 $s$ 倍 |
| NTK 感知 | 提高底数 | 可选少量 | 频率谱不再等比 |
| YaRN | 逐维分段缩放 + 温度 | 可选 | 要重标定、要改 kernel |
| 直接调底数 | 预训时就定好 | 不适用 | 短文本上要验 |

表里“继续训”那一列最容易误判。位置插值必须微调，因为它把相邻 token 的相位差直接压成了 $1/s$，模型看不到过那么密的间距；YaRN 与 NTK 不改位置、只改频率，不训也能跑，但“能跑”不等于“不退化”——短文本上的困惑度会变差一点，要验。

### 算一遍：继续训的账，与不继续训的账

外推方法真正差钱的地方在这里，算一遍就清楚了。

先算“把 8B 模型在 128K 上继续训”的代价。继续训的算力是 $6ND$，$N$ 是参数量，$D$ 是 token 数，6 是前向 $2ND$ 加反向 $4ND$。取 $D=8000$ 亿（公开报告里长上下文阶段常用的量级）：

$$6\times8\times10^{9}\times8\times10^{11}=3.8\times10^{22}\ \text{FLOPs}$$

按有效 $4\times10^{14}$ FLOPs/s 算，是 $9.6\times10^{7}$ 秒，即两万七千卡时。在千卡上跑一整天，按每卡时 3 美元是八万美元。

再算“只做位置插值加一千步微调”的代价。一千步、每步 400 万 token，共 40 亿 token，是上面那个数的两百分之一：百多个卡时，几百美元。

两个数字放在一起，解释了为什么长上下文总是“先外推、再继续训”：外推让它能跑，继续训让它能看；前者是几百美元的事，后者是几万美元的事。也解释了为什么不同的产品线在这里分岔——如果只需要在短时间、偶尔的请求上支持 128K，外推就够了；如果长文档是主营业务，只靠外推会在真实文档上被用户发现。

还有一笔隐性成本容易被漏。外推之后，短文本会退化一点，而短文本占了九成的流量。所以一个看上去“只影响长文本”的改动，实际上要在全流量上回归：短文本困惑度、短文本指令遵循、长文本检索，三套评测都要过。这也是一些团队宁可在大规模继续预训练里就把长度分成几级拉上去的原因——一次训练解决两件事，而不是修完这个弄坏那个。

这些方法的共同假设值得单独说：**它们都认为模型已经学到了位置语义，只需要重新标定坐标轴**。这个假设在"检索一个事实"这类任务上成立，在"跨 200 页做推理"上不成立——训练数据里根本没有这种依赖，标定得再准也补不出来。这就是下一节和第五节要处理的事。

### 注意力：把一条序列切到多张卡上

位置修好之后，第二堵墙是显存与算力。

单条序列放不下的原因不在权重。数据并行复制整个模型，张量并行把每层的矩阵切成几块，流水并行按层把模型分段，这三种办法动的都是权重与层，没有一种能让一条 50 万 token 的序列装进单卡。激活值的量级是每层 $O(Td)$，FlashAttention 已经把 $T^2$ 的打分矩阵消掉了，但每层仍要存 $O(Td)$ 的输入输出，几十层叠起来就是几百 GB。

序列并行把 token 维切开，每张卡负责一段。麻烦在注意力：第 $i$ 段的 query 要和所有段的 key、value 相乘。朴素做法是每层做一次全收集，把各段的 KV 汇聚到每张卡上，通信量随长度线性增长，卡越多越堵。

《Ring Attention》(2023) 把这件事改成了流水。它能成立，靠的是分块注意力的一个性质：一个 query 块对一组 KV 块的注意力可以按任意顺序累加，只要把每块的 softmax 统计量正确合并。在线 softmax 用三个量记录累加状态——已见块的最大 logit $m$、指数和 $\ell$、以及未归一化的加权和 $O$。新块带着自己的 $\tilde m,\tilde\ell,\tilde O$ 进来时，按

$$m'=\max(m,\tilde m),\qquad \ell'=e^{m-m'}\ell+e^{\tilde m-m'}\tilde\ell,\qquad O'=\frac{e^{m-m'}O+e^{\tilde m-m'}\tilde O}{\ell'}$$

重标定。$e^{m-m'}$ 这个因子在做的事是：最大值变了，之前累加的那些指数都要按新的基准重新缩放，否则两段的权重不在同一个尺度上。三个量都是逐行、逐元素的，顺序无关。

顺序无关就可以把外层循环拆到不同设备上。设每张卡分到长度 $c$ 的 query 块，共 $N_h$ 张卡围成一个环：

```text
每张卡：切出自己的 query/key/value 块（长度 c）
for layer in layers:
    O, m, l = 0, -inf, 0
    K_cur, V_cur = 本卡的 K, V
    for step in 1 .. N_h-1:              # 所有卡同时执行
        O, m, l = flash_step(Q_local, K_cur, V_cur, O, m, l)
        send K_cur, V_cur to next card
        recv K_next, V_next from prev card
        K_cur, V_cur = K_next, V_next
    O = O / l
    O = FFN(O)                           # 逐位置计算，不通信
```

每一步传的是 $4cd$ 字节（K 与 V 两块，bf16 每元素 2 字节），算的是 $4dc^2$ FLOPs。要让通信藏在计算后面，需要传一块的时间不超过算一块的时间：

$$\frac{4dc^2}{F}\ \ge\ \frac{4cd}{B}\quad\Longleftrightarrow\quad c\ \ge\ \frac{F}{B}$$

$F$ 是单卡算力，$B$ 是卡间单向带宽，比值 $F/B$ 就是这台机器的算术强度门槛。A100 配 NVLink（312 TFLOPS、300 GB/s）算出来约 1K token；同样是 A100 走 InfiniBand（12.5 GB/s），要 24.5K token。这条不等式解释了一个反直觉的现象：**跨节点的 ring 在 128K 这个量级上反而不好用**。128K 的序列摊到 8 台机器 64 张卡，每卡只有 2K token，远低于 24.5K 的门槛，通信完全暴露在计算之外，加卡不再变快。它真正适合的是块足够大的场景——几十万到上千万 token。

单卡激活从 $O(T)$ 降到 $O(c)$：一层要存当前 query 块、当前 KV 块、正在接收的 KV 块和输出，共六块，$6bch$ 字节，与序列长度无关。反过来这六块也定了下限，每张卡手里的序列不能短于 $6c$ 个 token，$c=1$K 时就是六千多 token 起步。

这套机制换来的是精确注意力，不是近似。论文在 32 张 A100 上把 7B 模型训到 100 万 token 上下文，长度是此前最好的省显存方案的 32 倍；换到 TPUv4-1024，序列推到 3000 万 token，256 倍。有一个工程细节必须提：因果掩码让各段的负载不均——第 1 段的 query 只看第 1 段，最后一段要看前面所有段，环上跑起来前面几步有一半卡在空转。实际实现会把序列按"之"字形分配（相邻的卡一段从前往后拿、一段从后往前拿），让每张卡分到的计算量接近。

序列并行不减少总 FLOPs，它只是把显存和算力摊开。这一点决定了它的适用边界：算力够、显存不够时它救命；算力本身就是瓶颈时，它帮不上忙——那要靠压缓存，或者换掉二次项本身。

### 并行策略的通信账：长序列反而更省

“长序列要加一层序列并行”这句话背后有一笔容易被忽略的对比：张量并行的通信量随 $T$ 线性增长，而计算在长上下文里随 $T$ 平方增长，所以两者的比例会随长度下降。

八路张量并行下，每层要做两次全归约，每次的字节数是 $b\,T\,d\times2$。取 $b=1$、$d=8192$、80 层、有效带宽 160 GB/s：

| 上下文 | 计算 | 通信 | 通信占比 |
|---|---|---|---|
| 8K | 323 毫秒 | 134 毫秒 | 41% |
| 32K | 2.1 秒 | 537 毫秒 | 26% |
| 128K | 18 秒 | 2.2 秒 | 12% |

计算一列按 8 卡合计 3.56 PFLOPS 的有效算力算，通信一列按 $4LTd$ 字节算。三行共同的规律是：**上下文越长，张量并行越“划算”**，因为计算涨得更快，通信被摊薄。这与“长序列需要更多并行”的直觉方向一致，但原因不同：后者是因为显存装不下，不是因为通信。

这张表还有一个实际用途：它能解释为什么短上下文的推理集群普遍用 $P=8$，而长上下文的预填充集群愿意用 $P=16$。前者通信占比四成，再加卡就不划算；后者通信占比一成多，加卡仍然近乎线性加速。判据就是那个占比，不需要实测。

### 缓存：改结构、改精度、改数量

推理的账比训练更难算，因为缓存在请求的整个生命周期里都占着显存，还随并发线性叠加。压它的办法分三层，作用点完全不同。

第一层改结构。分组查询注意力（Grouped-Query Attention，GQA）让若干个 query 头共享一组 KV 头，共享比例就是缓存缩小的倍数：70B 模型 64 个 query 头配 8 个 KV 头，缓存是完整多头注意力的八分之一。极端做法是多查询注意力（Multi-Query Attention，MQA），所有头共用一个 KV，缓存降到几十分之一，代价是表达能力受损，训练时容易退化。工程上的比例这几年一路往下走：Llama-2-70B 用 8 组，Llama-3 仍是 8 组，Qwen3-235B 降到 4 组配 64 个 query 头，也就是 16 比 1。压力来自上下文——128K 的场景里，缓存比权重更贵。

第二层改表示。多头潜在注意力（Multi-head Latent Attention，MLA）不共享头，而是把 K 和 V 一起压进一个低维潜向量。每个 token 每层只缓存两样东西：压缩潜向量 $c_t^{KV}\in\mathbb{R}^{512}$，和一份解耦的旋转位置键 $k_t^R\in\mathbb{R}^{64}$（这份在各头之间共享，只负责注入位置）。合计 576 个数，bf16 下 1152 字节，61 层就是每 token 70KB，不到 GQA 方案的四分之一。

这里有个必须回答的疑问：只存 512 维的潜向量，各头的 key 从哪来？答案是不需要显式还原。设上投影矩阵 $W_{UK}$ 负责把潜向量还原成某个头的 key，那么

$$q_t^\top k_s=\big(W_Qx_t\big)^\top W_{UK}c_s^{KV}=\big(W_{UK}^\top W_Qx_t\big)^\top c_s^{KV}$$

中间的等号只是把转置搬了个位置。右边说明：把 $W_{UK}^\top W_Q$ 预先乘成一个新矩阵，query 就直接同潜向量做点积，key 根本不必被算出来。这个技巧叫矩阵吸收，它让 MLA 在缓存上只付 512 维的钱，同时保留每个头自己的投影——这是它比 GQA 划算的地方。代价有三处：推理时多一次矩阵乘，训练时多一组投影，以及 key 不再显式存在，QK-Norm 这类依赖显式 key 的技巧用不了（Kimi K2 因此改用直接裁剪投影权重的 QK-Clip）。

第三层不改模型，改运行时。量化把每个元素从 2 字节压到 1 字节，8 位几乎无损；再往下要小心，key 的量化误差直接进 softmax 的 logits，异常值被指数放大，得按通道量化 key、按 token 量化 value 才稳。驱逐则按注意力权重丢掉一部分 token，只留累积得分高的"重击者"。

驱逐最容易踩的坑是只留最近。《StreamingLLM》(2023) 给过一组很干净的数：Llama-2-13B 在 65K token 的书上，稠密注意力的困惑度是 5641，只留最近 1024 个 token 是 5158——两者都很差；而在窗口里再塞回最前面 4 个 token，困惑度直接降到 5.40。原因在 softmax 的分母：

$$a_i=\frac{\exp(s_i)}{\sum_{j\in\mathcal{V}}\exp(s_j)}$$

$s_i$ 是 query 与第 $i$ 个位置的打分，$\mathcal{V}$ 是可见位置集合。分母不能为零，当前 query 与历史都不太匹配时，模型仍要把这一份概率质量放到某处。因果掩码让位置 0 对后面所有位置都可见，"永远可见"的起始 token 于是被训练成了默认的接收端。删掉它们不是丢了一条信息，是把分母挖走一块，所有后续位置的权重都跟着偏移。论文把前 4 个 token 换成换行符再测，困惑度仍能恢复，说明起作用的是绝对位置，不是内容。

三层的边界不同：GQA 与 MLA 是结构，必须在预训练前定死；量化与驱逐是运行时开关，可按任务调。它们可以叠加，但要分别验证——量化加驱逐的组合在短评测上看不出问题，在长距离检索上会很显眼。

### 数据：长度是一段一段加上去的

位置与系统都就位之后，剩下的是最难补的一块。模型在 4K 上训完直接跑 128K，位置插值能让困惑度不爆炸，但长距离检索仍然接近随机。原因在数据：4K 的样本里任意两个 token 最多隔 4K，模型没机会学"在第 100 页记住一个人名，在第 300 页用它"这种模式。

Llama-3 的长上下文阶段给了一份可查的配方：主预训练在 8K 上完成，之后把长度分六级逐步拉到 128K，这一步用掉约 8000 亿 token，占总量的百分之五左右。两个验收标准写得很具体——短上下文评测的分数完全恢复，且大海捞针任务在该长度上全对，两条都满足才进入下一级。最后 4000 万 token 把学习率退火到零，同时上调高质量数据的比例。为什么不在早期就训长序列？因为注意力算力随长度平方涨，早期用它换不到相应的收益。

Qwen3 的选择是把长上下文压缩成一个专门阶段：32K 序列上再训几百亿 token，其中 75% 的文档长度在 16K 到 32K 之间，25% 在 4K 到 16K 之间，同时把 RoPE 底数从 10000 提到 $10^6$，推理时用 YaRN 加双块注意力做四倍扩展。两种路线的差别是：把长度当成预训练的一部分，还是当成一次专门的适配。前者更贵，后者依赖外推改造的可靠性。

打包（packing）在这里有个容易忽略的细节。把多篇文档拼成一条长序列能提高利用率，但必须用注意力掩码隔开，否则模型会学到跨文档的虚假依赖。Llama-3 的报告里专门提到，这个改动在标准预训练里影响有限，在长序列继续训练里却很重要——短序列时跨文档的污染只发生在局部，长序列时它会一路传下去。

真实长文档稀缺，合成数据补上了另一块。常见做法是用强模型把短文档改写成需要跨章节引用的长文本，或者直接构造"把针埋进干草堆"式的检索样本。这类数据能教会模型定位，教不会它做全局推理。针的形状太规整：一句与上下文无关的事实，一个近乎唯一的句式，模型只需局部匹配就能命中。换成需要比对三处证据、或者统计全文出现次数的任务，同一批模型的表现会明显下滑，而后者才是合同审阅、代码库理解真正需要的能力。

### 一个失败案例：位置对了，全局次序还没对

有一个常见的错误诊断：模型在 32K 上单针检索全对，于是认为长度已经扩到位。拉到 128K 却发现，单针还是对，只要问“这两个小节谁在前面”“全文里这个数字出现了几次”，就开始错。

原因不在位置编码的覆盖范围。外推把相位折回了训练区间，模型确实能区分“第 10 万位”与“第 10 万零一位”，但它没有机会学到“第 10 万位在第 3 位之后十二万位”这类**跨尺度比较**。训练时段的 4K 里，任何两个位置的距离不超过 4096，对“相隔十二万”的相对次序，语料里一次样本也没出现过。位置外推只把坐标轴拉长了，没把语料里的依赖关系拉长。

第二个容易踩的坑是位置插值的副作用。把一个 4K 模型按 $s=32$ 插值到 128K，相邻 token 的相位差被压成原来的 1/32——第 100 与第 101 位在慢频率维上几乎一模一样。于是“复制上面那串序号”这类**局部次序敏感**的任务开始错位，而且是系统性错位，不是随机错。这恰好与上面那个跨尺度问题是两个方向：一个在大的那头缺，一个在小的那头糊。

两个问题对应两种不同的数据。前者要靠带“跨段落引用”的长样本，让模型见过“这个结论要回到第 200 页找依据”；后者需要靠微调把局部分辨率恢复回来——这也是位置插值必须配微调的原因，纯外推把相位折进去了，但模型没学过在密密的相位上分辨相邻。

所以验收一条长上下文能力，至少得三套题：单针（看有没有定位到）、多跳（看能不能跟着引用走）、局部次序（看密密的位置还分不分得开）。只看单针，会高估一大截。

### 接口：把 30 万字切成能喂的形状

一份 300 页的文档转成 token 约 25 万。它要么整份进去，要么切成块。选择哪一种不是技术偏好，是成本与召回的权衡，而权衡的两头都可以算。

整份进去：预填充 $2NT+4LT^{2}d$。70B、80 层、$d=8192$ 时是 $1.8\times10^{16}+1.7\times10^{17}=1.9\times10^{17}$，按八卡四成利用率算约 53 秒，单请求缓存 80 GB——一张 80 GB 卡装不下，得切开。这是“整份进去”在工程上的真实门槛：不是算不起，是装不下。

切块进去：按 4K 切，25 万 token 切成 60 块，检索召回 8 块，上下文回到 3.2 万。预填充降到 $1.3\times10^{15}+2.8\times10^{15}=4.1\times10^{15}$，1.2 秒，缓存 10 GB。代价是切断了跨块的依赖，以及召回不准时整题错。

两者之间还有一系列中间形态，每一种都对应一个具体的工程选择：

| 形态 | 上下文 | 首字延迟 | 主要风险 |
|---|---|---|---|
| 整份 | 25 万 | 53 秒 | 装不下、中段丢失 |
| 章节级 | 3 万 | 1.2 秒 | 章节切错 |
| 块级 + 重排 | 3 万 | 1.2 秒 | 召回漏掉关键块 |
| 块级 + 邻块扩展 | 5 万 | 2.5 秒 | 上下文变长、噪声多 |

第三行与第四行的差别值得单说。切块之后，一个常见的补救是“召回块周围各扩一块”，让段落的上下文完整。它把召回漏检率降下来，代价是上下文变长、噪声变多——而噪声恰好会触发第 5 节的 U 形曲线：中段的信息被忽略。所以扩块不是免费的，扩多少要看“关键信息在块内的位置分布”，这个分布可以统计出来，不必猜。

还有一条容易被忽略的接口细节：**块边界要按结构切，不按长度切**。按固定 4K 切，会把一个条款从中间切断，前半在上一块、后半在下一块，两块各自都不完整。按标题层级切（章节、条款），块长不均但语义完整。代价是要先解析文档结构，而 PDF 的结构解析本身就不便宜。

### 旋转在校前还是校后：一个实现陷阱

RoPE 把位置乘进键与查询，而缓存要存键。这两件事凑在一起，产生了一个选型问题：缓存里存的是旋转前的键，还是旋转后的键。

**存旋转后。** 写入时算一次旋转，读取时直接用。好处是每步少一次旋转，算量小；坏处是位置被烤进了缓存——想换缩放系数（比如运行中把 YaRN 倍数从 4 改成 8），已缓存的部分全部失效，得重算。

**存旋转前。** 缓存里是“与位置无关的键”，读取时现施旋转。好处是位置策略可以在请求层热切换，同一个前缀可以给不同长度策略的请求复用；坏处是每步多一次旋转，且反向传播要额外存相位。

旋转的算量可以算：每头每位置 $d_{\text{head}}$ 维，乘法次数 $2d_{\text{head}}$，加上正余弦查表。一层 32 头、128K 位置是 $2\times128\times32\times131072=1.1\times10^{9}$ 次乘法，折到 128K 解码的一步（平均位置 65536）是 $5.4\times10^{8}$，相对于那一步要读的 33 GB 只占很小的比例。所以“多一次旋转”在长上下文解码里几乎免费。

| 方案 | 每步额外算量 | 位置策略可热切 | 前缀可跳位置 |
|---|---|---|---|
| 存旋转后 | 无 | 不可 | 不可 |
| 存旋转前 | 约 $2\%$ | 可以 | 可以 |

表里第三列是两者的真正差距，也是最近越来越多引擎改存旋转前的原因：**它把“位置”从一个存储属性变成了一个计算属性**。一旦位置可以现算，同一份前缀就能同时服务不同长度策略的请求，而不必为每种策略存一份缓存。在混合流量（短对话 + 长文档）的服务里，这一条直接决定了缓存能不能复用。

代价是训练与推理的图多了一处差异：训练时相位是现成的，推理时要现算。数值上两者应该逐位一致（正余弦是确定性的），但 fp16 下的相位计算会引入微小差异，上线前要对拍。

### 三个可以当场测的误解

关于长上下文，有三个说法在讨论里反复出现，而且都能用一次实验推翻。

**“窗口开到多大，能力就到多大。”** 窗口是模型能接受的最大长度，有效长度是它真能用上的长度。RULER 那组数据的结论是：几乎所有模型在单针任务上接近满分，到 32K 就有一半掉到基准线以下。两者相差四倍，而产品宣传里只会写前者。判断自己的模型，要拿一个“多键回取”的题在目标长度上跑一遍，而不是看配置文件里的数字。

**“位置外推调个系数就行。”** 调系数能让困惑度不爆炸，但它不创造长距离依赖。位置插值把 4K 的模型拉到 128K，检索类任务的准确率仍然接近随机；需要继续训练的不只是“适应新相位”，还有“学会跨十二万位做比较”，后者靠语料而不是靠系数。

**“有了长上下文，就不用检索了。”** 两个数字能打消这个念头：语料涨十倍，预填充涨一百倍（平方项）；而召回准确率未必比向量检索高。长上下文真正擅长的场景是“把检索结果完整地读一遍”，而不是“把检索省掉”。在需要多跳比对的题上，它确实比检索强；在需要全库扫描的题上，它根本做不到。

三个误解共享一个根源：把“能接受”当成了“能用”。长度的每一个数字背后都有一笔不同的账，分别对应位置、数据、算力、评测，而它们完全可能停在不同的位置。一个模型可以宣称 128K、实际 32K、单针 128K 全对、多跳 16K 开始错——这四个数都可以是真的，只是回答了不同的问题。

### 有效长度：U 形曲线与 RULER

宣称 128K 的模型，在 128K 上还能用多少，需要一把尺子。

《Lost in the Middle》(2023) 给了一个不舒服的答案。做法很简单：准备 20 篇文档（约 4K token），把含答案的那篇放在不同位置，其余不动。准确率画出来是一条 U 形曲线——放开头或结尾，模型答得好；放中间，准确率明显掉下去，有时比不给文档还差。这个现象在专门为长上下文训练的模型上同样存在，只是谷底浅一些。论文的解释是两股偏置叠加：开头的文档被反复注意到（首因），结尾的文档离生成位置最近（近因），中间的被两头挤掉。

大海捞针式的测试太容易通过，因为它只要一次词面匹配、答案位置固定、干扰项弱。真正难的是多跳与聚合。《RULER》(2024) 把这些任务拆成四类共 13 个配置，每个配置都带难度参数，长度和难度因此可以分开扫。检索类 8 个，从单针（三种针型，其中一种是 32 位 UUID）到多键、多值（同一个键对应 4 个值，要求全取回）、多查询（4 个不同的键，同样要求全取回）；多跳追踪是一个变量链，`X1 = 12345` 后面接几条 `X2 = X1` 的绑定语句散在全文，要求把所有指向这个值的变量名都列出来；聚合类两个，常见词抽取与按幂律分布采样的高频词抽取；问答类把 SQuAD 与 HotpotQA 的短文题稀释到目标长度。

有效长度的定义是一条绝对分数线：以 Llama-2-7B 在 4K 上的 13 任务平均分 85.6% 为阈值，取平均分仍高于它的最大长度。用这条线量 17 个模型，结果是几乎所有模型在单针任务上接近满分，但到 32K 就有一半掉到线下；除了 Gemini-1.5-Pro（有效长度超出测试上限），没有一个能在自己宣称的长度上保持。Yi-34B 宣称 200K，在干扰针堆满全场的版本上，256K 时掉了 40 分。它的错误模式很有代表性：能圈到大体位置，但定位不到具体那个键，于是把附近的干扰值抬了回来。

为什么用合成任务而不是真实长文档：真实评测集的长度不好控，材料还可能早就在预训练里见过，分不清是读懂了还是记住了。合成任务把参数知识这条路堵住，代价是它测的是"能不能在长上下文里做这几类操作"，不是"能不能读懂一份真实合同"。两类评测不能互相替代。

退化的来源有三处，叠在一起就是"开头结尾清楚，中间模糊"。训练数据里长距离依赖本来就稀疏，模型学到的多是局部连贯；注意力在长序列上被稀释，softmax 把权重摊到几万个位置上，真正相关的几个 token 分不到足够份额；位置编码压缩之后角度差变小，局部次序与远处的相对位置同时变糊。三处都不在评测的控制变量里，这也解释了为什么同一份榜单上分数接近的两个模型，在实际文档上的表现能差出一大截。

### 成本：一次 prefill 与一次检索

回到账单。一次 prefill 的浮点运算分两块：

$$\text{FLOPs}\approx 2NT+4LT^2d$$

$N$ 是参数量，$T$ 是序列长度，$L$ 是层数，$d$ 是隐藏维。第一项是所有权重矩阵各乘一遍（每个参数两次运算：一次乘、一次加），第二项是注意力的两个矩阵乘：$QK^\top$ 与 $AV$，各 $2T^2d$，每层一份。取 70B、80 层、$d=8192$：4K 时权重项是 $5.7\times10^{14}$，注意力项 $4.4\times10^{13}$，不到一成；128K 时权重项涨到 $1.8\times10^{16}$，注意力项涨到 $4.5\times10^{16}$，反超两倍多。token 数涨 32 倍，总算力涨约一百倍。

换成时间更直观。八张 H100 在 40% 左右的算力利用率下约 $3\times10^{15}$ FLOPS，128K 的一次 prefill 要 20 秒上下，4K 只要 0.2 秒。首 token 延迟差一百倍，用户能直接感觉到。再叠上并发：单请求 40GB 缓存，每卡只能挂十二个，而 4K 时能挂三百多个。吞吐与延迟同时掉一个数量级，这就是长上下文定价普遍高于线性折算的原因。

对照检索方案，差距在一个数量级以上。把上下文压到 8K，prefill 回到 0.4 秒；检索本身的开销是算一次查询向量、在一批向量里做近邻搜索、再对几十个候选做重排，量级几十到几百毫秒。但它有自己的失效模式：切块会把跨段落的论证切断，召回的片段可能恰好缺了关键那句；它依赖查询与文档的字面或语义相似度，而很多问题需要把全文读完才知道该看哪里。

判断标准因此落回任务形态。需要全局聚合、跨文档比较、对全文结构做判断的，长上下文更合适；需要精确查找、知识频繁更新、语料规模远超窗口的，检索更合适；介于两者之间的常见做法是混合——先检索把范围缩到几十 K，再让模型在这个窗口里做多跳推理。有一个变量会改变结论：缓存能不能复用。同一份长文档被反复提问时，前缀缓存让后续请求跳过 prefill，长上下文的边际成本骤降；每个请求都换一份材料，这笔钱就要一次次重付。

序列方向的账到这里算得相当细了：位置怎么折、算力怎么摊、缓存怎么压、数据怎么配、评测怎么量。相比之下，深度方向的账几乎没人记过。从 2015 年到现在，残差连接一直把所有层的输出等权相加——这条规则只被打过补丁（缩放、正则化、门控），却从来没有被真正改造过。下一章就从这条唯一没被改过的规则讲起。
