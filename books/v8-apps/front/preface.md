# 前言

模型知道的东西，停在它的训练数据那一刻。而用户要问的事，一半在那之后，一半在公司的私有文档里。

这一册讲怎么把这两头接起来：让模型在上线之后还能看到新东西，还能动手做事。

十章分两块。

前六章讲检索。检索增强生成（RAG）这几年被说得太简单了——"把文档切块、向量化、召回、塞进提示"——真实项目里，九成的失败出在切块和评测上，而不是模型。这几章按数据流讲：为什么检索是必要的，切块怎么切，向量怎么建，混合检索怎么组合，上下文怎么拼，以及最关键的：怎么知道你的检索是好的。

后四章讲工具与 Agent。模型调用函数听起来是个接口问题，实际上是一堆设计问题：schema 怎么定、失败怎么处理、什么时候该停、状态放哪里、权限怎么收。Agent 循环最容易被写成一个"调到成功为止"的死循环，而生产环境里，它需要的是明确的终止条件、可观测的执行轨迹、以及出错时的回退。

这一册的立场比较务实：大多数所谓 Agent 需求，用一条固定的工作流就能做好；真正需要自主循环的，是少数。判断标准在第八章。

书里的例子尽量是小规模可复现的：几个文档、几十条查询、一个本地向量库。这些够说明原理，也够暴露问题。
