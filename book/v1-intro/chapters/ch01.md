## 一句话的下半截

设想你在手机上打字，输入“今天的天气真”，候选栏跳出“好”“不错”“热”“冷”。你还没打完，它已经在猜下一个字了。

语言模型做的就是这个：给定一段前文，给词表里每一个可能的下一个词打分，分数高的排在前面。它并不真的“知道”今天天气如何，它只是见过大量“天气真好”“天气真热”这样的句子，知道在这个位置，哪些词出现得多。

这件事听起来简单，却是过去几年所有能力的地基。原因在于，要把下一个词猜准，模型被迫学会的东西远不止词与词的搭配。

### 一个需要常识的预测

看这句话：

> 我把钥匙放在桌上，然后去开门，发现门锁着，于是我……

后面最可能接什么？“回家拿钥匙”“找房东”“敲门”。几乎不会接“把门拆了”，也不会接“去睡觉”。

要做出这个判断，模型得知道：钥匙能开门；门锁着通常是因为没带钥匙；人遇到这种情况会回去取。这些都不是语法知识，而是关于世界如何运转的常识。语言里到处都是这种隐含的常识，模型为了降低预测误差，只能把它们一点点吸收进去。

再看一个更细的例子。“奖杯放不进箱子，因为它太大”和“奖杯放不进箱子，因为它太小”，两句话只差一个字，前一个“它”指奖杯，后一个“它”指箱子。人几乎不用停顿就能分清，靠的也不是语法规则，而是“装不进去”可能是东西太大、也可能是容器太小这类日常经验。研究者专门用这类句子测过模型，早年的模型经常指错，规模变大之后才逐渐答对。这个变化本身就是线索：指代不是查表能解决的，得先有关于世界的粗浅认识。

这也是为什么“预测下一个词”不是一个浅薄的目标。语法、指代、事实、因果、甚至多步推理，都会影响下一个词是什么。模型猜得越准，说明它内部压缩的规律越多。

### 对话能力是从哪来的

你可能会问：既然只是预测下一个词，它为什么会回答问题？

因为对话本身就是文本。网页、论坛、客服记录、教科书里，到处是“问—答”的结构。模型在预训练时见过无数个“有人问……，有人答……”的片段，于是学会了：看到一个问题，接着往下写，最自然的续写就是一个回答。

严格说，对话在模型眼里只是一段带格式的文本。你和它的往来会被拼成一条长字符串，里面有“用户说”“助手说”这样的标记，标记的写法由训练时的模板决定。所谓“角色”，是这段文本的结构，不是它内部的某个开关。它没有“我正在跟谁说话”的状态，只有“这段文本接下来最像什么”。

这一点解释了很多人误以为的神秘现象。你在一个新窗口里重新介绍自己，它会忘掉上一次的对话，因为上一次的文本根本不在这次的输入里。你在一段很长的对话中途改变话题，它有时会把前面的话题带进来，因为那些文字还在输入里。它没有记忆，只有当前这段文本。

后来的指令微调（第三卷会讲）把“问—答”这种模式进一步强化：用大量“指令—回答”的样本告诉模型，什么时候该停、该用什么格式、该回答谁。但底层的能力仍然是同一个：根据前文，预测接下来最合适的词。

### 模型看到的不是字，是 token

模型不直接读汉字或字母。文本先被切成 token：一个 token 可能是一个词、半个词、一个汉字，或者一个标点。

切法有讲究。英文里，常见词往往整块保留，生僻词被拆成几段：unbelievable 大概会切成 un、believ、able 三块，tokenization 可能切成 token 和 ization。中文里常用的双字词有时占一个 token，生僻字则可能被拆得更碎。数字是最容易被忽略的地方，2024 这样的四位数经常被切成“20”和“24”两段，所以模型做算术时看到的不是两千零二十四，而是两个碎片。

词表的大小是十万量级。各家公开的词表大致落在五万到二十万之间，估算方法是直接去看分词器配置文件里的条目数——那是一个可以数出来的整数，不是估计。词表在训练开始前就定死，之后不再改动。模型的所有输入输出，都在这十万个格子里挑。

模型在 token 序列上做预测：给定前面若干个 token，猜下一个 token 是什么。这带来几个容易被忽略的后果。

它数不清字数。你让它写“正好 500 字”，它只能大致估，因为它的计数单位是 token，不是字。它也很难逐字反转一句话，因为在它眼里那不是一个个字，而是一段段碎片。

同一个意思，用中文说和用英文说，token 数可能差近一倍。价格按 token 计，上下文窗口也按 token 计，所以同一条请求换一种语言，成本和能装下的内容都会变。这也是为什么很多团队在内部提示词里混用英文缩写，未必是崇洋，纯粹是省钱。

### 为什么同一个问题，每次回答不一样

模型输出的不是一个确定的句子，而是每个位置上所有候选 token 的概率。真正生成时，系统按这些概率抽样：概率高的 token 更容易被选中，但不是必然。

抽样时可以调“温度”。温度低，概率高的候选几乎必选，回答稳定、保守；温度高，低概率的候选也有机会，回答多样，但更容易跑偏。这就是为什么同一个问题问两次，可能得到两个措辞不同、甚至结论略有出入的答案。

除了温度，还有一类做法是先砍掉长尾：只在前几个最可能的候选里抽，或者只保留累计概率足够高的那一小撮，剩下的直接排除。这样既保留了随机性，又不会抽到一个明显不合适的词。写作类任务通常把随机性调高一点，抽取信息、写代码、做分类时则调低，甚至完全关掉。

它不是一个查表系统，每次都在重新抽样。

### 预测得准，等于压缩得好

还有一个视角，能解释很多现象：预测和压缩是同一件事。

把一段文本看成比特流。如果模型能给下一个 token 分配很准的概率，那么编码这段文本所需的比特就更少；预测得越准，压缩率越高。训练语言模型，本质上是在用参数去逼近文本的统计规律，把“意外”压到最低。

这个视角有个直接推论：越是常见的内容，模型压得越好，复述得越准；越是罕见、独特的内容，压缩时丢掉的细节越多。你让它背一段广为流传的诗，它一字不差；你让它复述某份内部文档里的第三段，它会给你一个语气很像、内容不对的版本。不是它不认真，是那部分信息在压缩时本来就没被留住。

这个视角也解释了幻觉。压缩是有损的：模型记住的是规律，不是原文。当它被问到训练数据里没有、或记不清的细节时，它不会空着，而是用最像的规律补上一个合理的答案。补得越流畅，越容易被当成真的。

### 它为什么会犯错

错误有很多种，来源不一样，处理方式也不一样。把它们混在一起谈，就容易得出“它不靠谱”或者“它很聪明”这两种同样粗糙的结论。

一类错误来自数据。训练语料里本来就有的错误、过时的说法、以讹传讹的结论，会被一起学进去。如果某个错误说法在语料里出现得足够多，模型甚至会把它当成常识。这类错误的特点是稳定：你问十次，它错十次，而且错得一模一样。

一类错误来自压缩。前面说过，参数存的是规律不是原文。细节越具体，越容易在压缩中失真。问它某个具体日期、某个编号、某本书的第几页，它给出的答案往往是“形状正确、内容随机”。

一类错误来自抽样。同一个问题，温度调高之后两次回答可能互相矛盾。这不是它在改主意，是两次抽到了不同的路径，而每条路径单独看都说得通。

还有一类错误来自训练目标本身。它被训练成“给出一个像样的续写”，而不是“在不确定时停下来”。所以在它不知道的时候，最自然的行为不是承认不知道，而是生成一段看起来像答案的文字。后训练会专门教它说“我不确定”，但这是在跟预训练养成的习惯对抗，不可能完全成功。

认清这四类来源，你就能大致判断什么时候该核对：涉及具体数字、日期、引用、人名，几乎总要核对；涉及风格、结构、改写、头脑风暴，通常可以直接用。前者是压缩的弱项，后者正是压缩的强项。

### 三个常见的误解

第一个误解是“它在理解语义”。这个说法不能算错，但容易让人想歪。它处理的确实是 token 之间的关系，而这些关系里包含了大量语义信息；它能区分“打”在“打车”和“打人”里的不同，说明它抓到了某种类似含义的东西。但它没有指称，没有经验，也没有一个“我明白了”的时刻。说它“理解”，是一种方便的说法，边界在于：它能处理语言里被写下来的那部分规律，处理不了没被写下来的部分。

第二个误解是“它记住了我说的话”。权重是训练完就冻结的，你和它的对话不会写回权重。所谓“记住”，只是这段对话还在当前输入里。窗口一关，或者对话长到超出上下文长度被截断，那些内容就真的没了。这也是为什么重要的设定要写进系统提示词，而不是指望它“记住上次说的”。

第三个误解是“它答得流畅，所以它确定”。流畅是训练目标，不是置信度信号。一段话读起来顺，只说明它在语言模型的打分里概率高，不说明事实为真。反过来，它有时会用很犹豫的语气说出正确答案。判断可信度不能看语气，得看这件事是否可验证、是否是它训练数据里的常见内容。

### 它不是什么

理解大模型，很多时候靠的是划清边界。

**它不是数据库。** 参数里存的是统计规律，不是原文。你问它某本书第 37 页写了什么，它可能编出一段很像样的文字，而不是告诉你“我记不清”。这就是幻觉。

**它不是搜索引擎。** 它不知道今天发生了什么，除非有人把新信息放进上下文，或者给它接上检索工具。它的知识有一个截止日期，这个日期由训练数据的采集时间决定，而不是由它自己决定。

**它不是计算器。** 它见过很多算式，但没有真正的算术单元；多位数乘法、长除法这类任务，它经常在中间某一步算错，而且错得很自信。近两年的模型会通过写中间步骤、或者调用外部计算工具来绕开这个弱点，但那是补偿，不是它长出了算术能力。

**它没有稳定的目标。** 它不会“想帮你”，也不会“想骗你”；它只是在给定上下文下，输出概率最高的续写。所谓“听话”“有帮助”，是训练时被塑造出来的行为。

这些边界不是永久不变的。工具调用、检索、推理时的额外计算，都在把边界往外推。但无论怎么推，知道它此刻的边界在哪里，是使用它的前提。

### 为什么是现在

“预测下一个词”这个想法并不新。2003 年就有人用神经网络做这件事，2013 年词向量已经很成熟。但直到 2017 年 Transformer 出现、2018 年之后算力跟上来，它才变成今天的样子。

三个条件同时满足，事情才发生。

**数据**：互联网上有足够多的文本。万亿级 token 的语料，才够让模型见到足够多的语言现象。

**算力**：GPU 把大批重复的乘加做得极快，几千张卡可以连续训练几个月。没有这个，模型再大也训不完。

**结构**：Transformer 能把一条序列的所有位置并行计算，正好吃满 GPU 的吞吐。换成循环网络，同样的算力要慢一个数量级。

三者缺一不可。这也是为什么大模型集中在少数有数据、有卡、有工程能力的团队手里。

还有一个不太显眼但同样关键的条件：人们发现规模变大之后，效果不是线性变好，而是平滑、可预测地变好。这条规律让投入变得可以计算——多花十倍算力大约能换回多少提升，事先能估。在这之前，训练大模型更像赌博；在这之后，它成了一项可以立项、可以排期、可以写进预算的工程。

### 一个不太准确但有用的类比

可以把大模型想成一个读过很多书、但记不清细节的实习生。

它见过大量文本，知道常见的说法、结构、事实的大致轮廓；你给它一个任务，它能很快写出一个像样的初稿。但它不查证，不核对，不确定的地方会用流畅的句子补上；它也没有稳定的常识，偶尔会在简单的地方犯低级错误。

这个类比不精确——它不是人，没有意图，也没有“记忆”这种东西——但它能帮你建立正确的使用习惯：把它当起草工具，而不是权威；重要的数字、引用、结论，自己核一遍。
