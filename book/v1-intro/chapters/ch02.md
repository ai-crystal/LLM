## 一次生成的全过程

凌晨一点，你在输入框里敲下一行字：“帮我把这段话改得更客气一些，但别太生硬。”按下回车。

光标闪了一下，屏幕空白了半秒，然后文字开始一个一个出现，速度跟你朗读差不多。中途它停了一下，像是在斟酌，接着继续。整段话写完，用了不到十秒。

那半秒里没有人在看你的句子。机房里没有人拿起你的文字读一遍，也没有一个程序在“理解”你想表达什么。有的只是一串固定顺序的计算，原料是你的文字，成品是下一个字。

### 按下回车的那一秒

你的请求先离开这台机器。文字被装进一个结构化的请求，带上模型的名字、几个参数，通过网络送到机房。如果同时有很多人在用，它还要在队列里等一会儿，等到有一块显卡腾出手来。

轮到你的时候，真正的工作才开始。你的文字会被切成一段一段的碎片，每个碎片换成一个编号，每个编号换成一组数字，这组数字往上传几十层，最后在十万个候选里算出谁更合适，抽一个出来接在后面。这个字接上去之后，整段文字变长了，于是从头再来一遍，产出下一个字。

所以“生成一段话”不是一次计算，而是几十次、几百次同样的计算首尾相接。每一次只产出一个 token，产出之后立刻回到起点重新走一遍。理解大模型，很大程度上就是理解这个循环里每一步在做什么，以及哪些步骤可以省、哪些省不掉。

### 文字先被切成 token

模型不认识汉字，也不认识字母。它认识的只有整数编号，所以第一步是把文字翻译成编号。

这件事由分词器完成，它和模型是两样东西。分词器是一段规则固定的程序，通常在训练开始前就定好，之后不再改动。它的工作方式是反复合并：从单个字符出发，统计语料里哪两个相邻片段最常一起出现，把它们合并成一个新片段，然后在新的片段集合上再统计、再合并。这个过程重复几万次，最后得到一个十万量级的词表。

合并的结果很有意思。出现频率高的片段被合成整块，频率低的仍然是碎片。英文里 the、and、ing 这类高频片段各占一个 token，unbelievable 这种词会被拆成 un、believ、able 三段。中文里“人工智能”这种常见组合可能整块保留，“玻璃”可能被拆成两个 token，一个生僻字则可能被拆成两三个字节级的碎片。空格也有讲究：多数分词器把空格算进后一个词里，“ the”和“the”是两个不同的 token。这解释了一个很多人遇到过的现象：在提示词里多加一个空格、或者换行方式不同，模型的反应会微妙地变化。

数字是最反直觉的地方。2024 这样的四位数，通常被切成“20”和“24”；再长一点的数字会被切成三位一组。所以模型看“1234”的时候，看到的不是一千二百三十四，而是两块碎片。它做算术容易在进位的地方出错，根源就在这里——它没有“位”这个概念，只有碎片。

词表大小可以直接查：主流模型公开的分词器配置文件里，条目数是几万到二十万之间的一个整数，十万量级这个说法就是这么来的。分词器一旦确定，同一个意思用不同语言写的成本差异也就确定了。中文一个汉字通常落在一到两个 token，同样的意思用英文写，token 数往往少一些。这就是为什么按 token 计费时，中文请求常常比英文贵。

切完之后，你的句子变成了一串整数，长度可能比你想象的短，也可能比你想的长。一段八百字的中文，大约一千多个 token，估算方法就是一个汉字按一到两个算。这个数字决定了后面所有的账：显存、延迟、价格。

### 每个 token 变成一个坐标

拿到编号之后，模型去查一张表。这张表有十万行，每行几千个数，行号就是 token 的编号。查出来的这组数，叫这个词的向量表示，或者嵌入。

这组数不是人写的，是训练出来的。训练结束后，意思相近的词，坐标也相近：猫、狗、宠物这几个词在空间里挤在一起；星期几的几个词排成一小簇；动词和名词各占一片区域。有人在里面做过加减法，发现“国王”的坐标减去“男人”再加上“女人”，最接近“女王”。这个例子常被讲得太神，它其实只说明一件事：坐标的几何关系编码了词语用法的相似性，没有更多。

一个词只有一个坐标，麻烦就来了。英文的 bank 既是河岸也是银行，中文的“打”既是击打也是打车、打电话。一个坐标装不下这么多意思，所以模型必须靠上下文来区分。这件事不是在这一步做的，而是在后面那几十层里做的。

还有一件事要补上：光有编号不够，还得知道先后。“狗咬人”和“人咬狗”用的是同一批 token，顺序不同，意思完全相反。所以每个位置还会额外混入一个随位置变化的标记，让模型能分清谁在前谁在后。做法有很多种，效果都是给每个位置盖一个“第几个”的戳。

到这里，输入变成了一串向量：长度等于 token 数，每个位置几千个数。接下来这串东西要往上传。

### 几十层：每个词都在回头看

模型的主体是几十层相同的结构叠在一起。常见是三十到一百层，具体数字在模型的配置文件里写着，不需要猜。每一层做两件事，一件叫注意力，一件叫前馈。

注意力解决的是“这个词该参考谁”。每个位置会算出三样东西：一个“我在找什么”，一个“我能被什么找到”，一个“我携带什么信息”。第一样拿去和前面每个位置的第二样比对，比得越合，说明那个位置越相关，于是从那个位置取走更多第三样。说白了，每个词都在向前面的所有词取证，取证的多少由相关性决定。

举个具体的句子：“小明把书递给小刚，因为他要考试了。”这个“他”指谁？模型在处理“他”这个位置时，会拿它的“我在找什么”去和前面每个位置比对，发现“小刚”和“考试”这两处的匹配度更高，于是主要从小刚那里取信息。到了更靠后的层，这个判断会被进一步确认和利用。前面的层多看相邻词和语法搭配，中间的层多看指代和句法结构，后面的层才处理“谁对谁做了什么”这种语义角色。这种分层不是设计出来的，是训练过程中自己长出来的。

注意力有一个硬性限制：只能看左边，不能看右边。因为训练目标是预测下一个词，如果允许看右边，等于考试时把答案摆在桌上。这个限制叫因果遮罩，实现上就是把右边位置的匹配度直接作废。它带来一个后果：模型处理一句话时是从左往右推进的，每个位置看到的世界，只到它自己为止。

一次注意力里，上面这套取证过程会并行做几十遍，叫多头。不同的头关注不同的关系：有的头几乎只盯着前一个词，有的头盯着句首，有的头专门找动词和它的宾语，还有的头在人名之间来回看。没有人告诉它们该盯什么，分工是训练出来的。你能观察到这些模式，但不能指定。

注意力之后是前馈。每个位置单独过一个小的网络，先变宽，再变窄，回到原来的维度。它不看别的词，只加工自己刚收集到的信息。一种比较被接受的理解是：注意力负责搬运和汇总，前馈负责把汇总结果对应到具体的模式和事实上——某些神经元会对“巴黎是法国的首都”这类关联特别敏感。

每做完这两件事，输出会加回到输入上，这叫残差。它的作用像在草稿上不断批注，而不是每层重写一张纸。没有这个加法，几十层叠起来会越算越偏，深层的信号传不上去。层与层之间还有归一化，把数值拉回一个稳定的范围，防止越乘越大。这两样东西本身不产生任何“智能”，但没有它们，深的东西就叠不起来。

走完最后一层，每个位置都有一个向量。要预测下一个词，只需要最后一个位置的向量——因为它是唯一一个“看完了全部前文”的位置。这一点在后面解释缓存时还会用到。

### 十万个分数，一次抽签

最后一个位置的向量，还要再换一次：乘上输出那张表，得到十万个分数，词表里每个 token 一个。

这些分数叫 logits。它们可以是任意实数，有正有负，大小没有上限，本身没有意义，只有相对大小有意义。分数高，表示在这个上下文里这个 token 更搭。

分数要变成概率，中间过一道 softmax。它的做法分两步：先把每个分数取指数，让差距被放大；再把所有结果按总和归一，使它们加起来等于一。放大的效果很关键——原来只领先一点点的候选，变成概率上领先很多。这解释了模型为什么有时候显得“斩钉截铁”：不是因为它的证据强，而是因为这一步把微小的领先放大了。

到这一步，模型的一次前向计算就结束了。它的全部产出，是十万个数构成的一个分布。注意，它没有“选”任何东西，只是给出了每个候选的权重。

选，是下一步的事。系统按这个分布抽一次签：权重大的更容易被抽中，但权重小的也有机会。这就是采样的基本形态。

为什么不用“取最大的那个”？因为那样会让输出变得极其呆板：同一句话永远接同一个词，遇到一次错误就一路错下去，写出来的东西重复、僵硬、缺乏变化。抽样带来了多样性，也带来了不确定性——同一个问题问两次，得到两个答案，根源就在这一次抽签。

抽签之前通常还有两个旋钮。一个是温度：它先把所有分数按同一个比例缩放，再走 softmax。温度低于一，差距被放大，分布变尖，高分的候选几乎必中，输出稳定保守；温度高于一，差距被压平，长尾候选也有机会，输出多样，但更容易跑偏。另一个是截断：只保留累计权重达到某个比例的那一小撮候选，剩下的直接排除，再在剩下的里面抽。它防的是“万一抽到一个语法上说得通、语义上很离谱的词”。

抽出来的是一个 token 编号。这个编号被送回分词器，翻成文字，接在屏幕上的句子里。然后整段文字——包括刚加上的这个字——重新作为输入，走一遍刚才的全过程。

### 第一个字为什么慢，后面的为什么快

用秒表量一下会发现一个规律：第一字出来得慢，后面越出越快。同一段回答，前面的字像是挤出来的，后面就顺了。

原因是这两个阶段的计算方式完全不同。

第一阶段叫预填充。你输入的整段文字一次性送进模型，所有位置同时计算。因为注意力允许每个位置看它左边的所有位置，而这些位置都已经存在，所以这一整批计算可以并行铺开，把显卡的计算单元喂满。输入越长，这一步越久，但摊到每个字上其实很便宜。

第二阶段叫解码。生成第二个 token 的时候，情况变了：前面那些位置的计算结果，其实一点都没变。它们的向量只依赖它们左边的内容，而左边的内容已经固定。既然没变，就没必要重算——把它们存下来，后面直接查。

存下来的东西叫 KV 缓存，也就是每个位置在每一层算出的“我能被什么找到”和“我携带的信息”这两份记录。打个比方：一屋子人开会，第一次每个人做完自我介绍，把要点写在墙上的白板；后面每来一个新话题，只需要带着问题去白板上查，不必让所有人重新自我介绍一遍。没有白板，每说一句话就要全员重来，会开不完。

有了缓存，解码每一步只需要处理新来的那一个 token：算它自己的三样东西，拿它的“我在找什么”去查全部历史记录，再把结果往前传。计算量小了一个数量级。

但还有一个绕不过去的成本。解码每一步都要把整个模型的参数从显存里读一遍——几百亿到上千亿个数——而算出来的只是一个 token。所以这一步的瓶颈不在算力，而在搬运速度。显卡的计算单元大部分时间在等数据。这也是为什么同样的模型，换一张显存带宽更高的卡，出字速度能明显变快，而换一张算力更强、带宽没提升的卡，出字速度几乎没变化。

缓存不是免费的。每个 token 在每一层都要留两份记录，粗算一下：层数乘以二，再乘以向量维度，再乘以每个数占的字节数，一个 token 就是几十万字节到几兆的量级；攒到一万 token，就是几 GB 到几十 GB 的显存。这段显存不能给别人用，于是同时能服务的人数被压下来。长上下文之所以贵，根子在这里：不是算得慢，是存不下。

机房里还有一个优化：批处理。既然解码每一步的主要开销是读一遍权重，那就让很多人的请求共用这一次读取——把几十上百个请求拼成一批，一起读、一起算。这样每张卡服务的人多了，单位成本降下来，代价是每个请求都要等一等，延迟变高。

### 它在哪里停下

生成不会自己“想完”。停下来，是因为某个条件被触发。

最常见的是模型自己给出一个特殊符号。训练语料里每段文本的结尾都有一个结束标记，模型见得多了，学会在该结束的地方给这个标记高分。这个标记不会显示在屏幕上，它一出现，循环就终止。这是学出来的行为，不是硬编码的规则。

还有几种外部条件。接口通常有一个最大生成长度，到点直接截断，可能出现半句话。也可以设置停止词，程序在输出里匹配到某个字符串就切断——这时候模型并不知道自己被切了，它只是在写，写到一半被拿走。上下文窗口满了也会停：输入加输出超过上限，要么报错，要么把最早的内容挤出去。

知道机制，就能解释几种常见故障。

一种是停不下来。模型进入循环，反复说同一句话，或者绕着同一个意思打转。原因是它每产出一个 token，这个 token 就变成了下一轮的前文；前文越来越像它自己刚写的东西，于是它越来越确信“接下来还是这个”。自回归生成会自我强化，走偏了很难自己拐回来。

一种是话说一半。结束标记的概率偶然升高，循环提前终止；或者停止词被误伤，正文里恰好出现了那个字符串。

还有一种更根本的限制：它不会回头改。已经抽出来的 token 立刻变成下一轮的前文，覆水难收。所以它写长文时，前面某个判断错了，后面会一路顺着错下去，而且越写越自信。这也是为什么让它先列提纲再展开有用——提纲是它给自己造的前文约束，把后面的自由度收窄了。

到这里，一次生成的链条就走完了：切分、查表、叠层、打分、抽样、拼接，再从头来一遍。整条链上每一步都由同一批数字决定——哪个 token 和哪个 token 相邻，哪个位置该多看谁一眼，哪个候选该给高分。这批数字叫权重，几百亿到上万亿个，训练完就固定下来。

它们不是天生的。下一章要讲的，是这批数字怎么被造出来：从一座装满网页的机房开始，经过几万亿次填空，再经过两轮改造，最后被压进一张显卡。
