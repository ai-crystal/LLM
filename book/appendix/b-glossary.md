Token：
:   文本经过分词器切分后的最小单位。一个汉字通常对应一到两个 token，英文单词可能被拆成若干子词。

自回归（Autoregressive）：
:   按从左到右的顺序逐 token 生成，每一步都以已生成的序列为条件。GPT 系列的基本生成方式。

因果掩码（Causal Mask）：
:   注意力中的上三角遮罩，阻止位置 $t$ 看到 $t$ 之后的内容，保证训练时的并行计算与推理时的逐词生成一致。

KV 缓存（KV Cache）：
:   推理时缓存历史位置的键和值，避免每生成一个 token 都重算整个前缀。大小随层数、头数、上下文长度线性增长。

RoPE：
:   旋转位置编码。把 query 和 key 按位置旋转一个角度，使点积只依赖相对位移，是目前主流的位置编码方案。

GQA：
:   分组查询注意力。多个 query 头共享一组键值头，在 MQA 与 MHA 之间取折中，主要用于压缩 KV 缓存。

MLA：
:   多头潜在注意力。把键值压缩到一个低维潜向量，推理时把上投影吸收进权重矩阵，进一步降低缓存占用。

MoE：
:   混合专家。把前馈网络拆成多个专家，每个 token 只激活其中少数几个，用稀疏计算换取更大的总参数量。

路由（Routing）：
:   MoE 中决定 token 分配给哪些专家的机制，通常是一个小的线性层加 top-k 选择。

负载均衡损失（Load Balancing Loss）：
:   防止路由塌缩的辅助损失，惩罚专家之间的 token 分配不均。

ZeRO：
:   数据并行下的显存优化方案，把优化器状态、梯度、参数分片到不同设备，分为三个阶段。

张量并行（Tensor Parallelism）：
:   把单层内的矩阵按行或列切开，分散到多张卡上计算，每层需要两次全归约通信。

流水并行（Pipeline Parallelism）：
:   按层把模型切成若干段放在不同设备上，前后段以微批的方式流水执行，会产生气泡。

FlashAttention：
:   通过分块与在线 softmax 把注意力计算留在片上内存，减少对显存的读写，不改变数学结果。

RMSNorm：
:   只做均方根缩放的归一化，去掉了均值中心化，计算更省，训练稳定性依赖其他技巧配合。

SwiGLU：
:   带 SiLU 门控的前馈结构，比标准 ReLU 前馈多一组投影，在同等参数下通常效果更好。

muP：
:   最大更新参数化。一套让超参数（尤其是学习率）在不同宽度下可迁移的缩放规则。

缩放定律（Scaling Law）：
:   损失随参数量、数据量、计算量呈幂律下降的经验规律，用于在训练前估算预算分配。

Chinchilla 配比：
:   在给定训练算力下，参数量与训练 token 数大致同比例增长，约每个参数 20 个 token。

SFT：
:   监督微调。用指令与回答的配对数据继续训练预训练模型，让它学会对话格式与任务形式。

RLHF：
:   基于人类反馈的强化学习。先用偏好数据训练奖励模型，再用强化学习优化策略。

奖励模型（Reward Model）：
:   输入一个回答，输出标量分数，训练目标是让被偏好的回答得分更高。

PPO：
:   近端策略优化。通过裁剪重要性采样比率限制每次更新的幅度，是 RLHF 最常用的强化学习算法。

KL 散度：
:   衡量两个分布的差异。RLHF 中用它约束策略不要偏离参考模型太远，防止奖励黑客。

DPO：
:   直接偏好优化。把偏好学习写成分类损失，跳过显式奖励模型与在线采样。

GRPO：
:   组相对策略优化。对同一问题采样一组回答，用组内均值作为基线估计优势，省去价值网络。

RLVR：
:   带可验证奖励的强化学习。奖励由规则判定（答案是否正确、代码是否通过测试），不依赖奖励模型。

思维链（Chain of Thought）：
:   让模型在给出答案前先写出中间推理步骤，把隐式计算展开成可见的 token。

过程奖励模型（PRM）：
:   对推理的每一步打分，而不是只对最终答案打分，用于搜索与重排。

测试时计算（Test-Time Compute）：
:   在推理阶段投入更多采样、搜索或验证，换取更高的准确率。

RAG：
:   检索增强生成。先从外部知识库检索相关片段，再把它拼进上下文让模型据此作答。

重排（Rerank）：
:   对初步召回的候选片段做精细打分排序，通常用交叉编码器。

投机解码（Speculative Decoding）：
:   用小模型快速草拟若干 token，再由大模型一次并行验证，在不改变分布的前提下加速生成。

量化（Quantization）：
:   用更低的位宽表示权重或激活，减少显存占用并提升吞吐，代价是精度损失。

蒸馏（Distillation）：
:   用大模型的输出（概率分布或生成文本）训练小模型，把能力迁移过去。

剪枝（Pruning）：
:   去掉不重要的权重或结构，降低参数量与计算量。

连续批处理（Continuous Batching）：
:   请求结束立刻换入新请求，而不是等整批完成，显著提高 GPU 利用率。

分页注意力（PagedAttention）：
:   把 KV 缓存切成固定大小的块，用页表映射逻辑位置与物理显存，消除碎片并支持共享。

前缀缓存（Prefix Caching）：
:   复用相同系统提示或长文档已经算好的 KV，避免重复预填充。

MFU：
:   模型浮点利用率。实际达到的 FLOPs 与硬件峰值的比值，训练中通常在 40% 上下。

TTFT / TPOT：
:   首 token 延迟与每 token 输出时间，是推理服务最常用的两个延迟指标。

智能体（Agent）：
:   由模型、工具、循环与记忆组成的系统，能根据观察采取行动并推进多步任务。

MCP：
:   模型上下文协议。用统一接口把外部工具与数据源暴露给模型，减少每个应用重复适配的工作。

上下文窗口（Context Window）：
:   模型一次能处理的最大 token 数，包括输入与输出。

有效上下文（Effective Context）：
:   模型真正能稳定利用的长度，通常明显小于宣称的窗口大小。

灾难性遗忘（Catastrophic Forgetting）：
:   在新数据上继续训练时，模型丢失先前学到的能力。

数据污染（Contamination）：
:   评测题目出现在训练数据中，导致分数虚高。

pass@k：
:   采样 $k$ 次至少有一次正确的概率，用于衡量代码与数学任务的解题能力。

LLM-as-judge：
:   用强模型给回答打分或做 pairwise 比较，成本低但存在位置、长度与自我偏好等偏差。
